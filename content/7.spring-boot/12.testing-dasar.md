Sejauh ini kita menguji aplikasi secara **manual**: jalankan → buka Postman → kirim request → intip response. Sekali dua kali tidak masalah. Tapi bayangkan setiap kali mengubah kode, kita harus mengulang semua pengujian itu untuk memastikan fitur lama tidak rusak.

**Testing otomatis** mengubah pemeriksaan itu menjadi kode yang bisa dijalankan ulang kapan pun — dalam hitungan detik.

```text
Manual:  jalankan app → Postman → klik-klik → lihat  (5 menit)
Otomatis: ./mvnw test                                (10 detik)
```

---

## 1. Dependency Testing

Kabar baik: **tidak perlu menambah apa pun**. Sejak proyek dibuat, `pom.xml` sudah memuat:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

Starter ini membawa satu paket lengkap:

| Library | Peran |
| :--- | :--- |
| **JUnit 5 (Jupiter)** | Framework test: `@Test`, assertion, lifecycle |
| **Spring Test** | `@SpringBootTest`, `MockMvc`, context testing |
| **AssertJ** | Assertion yang lebih ekspresif |
| **Mockito** | Membuat mock (objek palsu untuk test) |
| **JSONassert / JsonPath** | Memeriksa isi JSON |

## 2. Test Pertama: Java Murni

Kita mulai dari yang paling sederhana — test tanpa Spring sama sekali, agar konsepnya jernih.

### Ganti seluruh isi file test

```text
src/test/java/com/example/belajarspringboot/BelajarSpringBootApplicationTests.java
```

```java
package com.example.belajarspringboot;

import static org.junit.jupiter.api.Assertions.assertEquals;

import org.junit.jupiter.api.Test;

class BelajarSpringBootApplicationTests {

    @Test
    void additionShouldBeCorrect() {
        int result = 2 + 3;
        assertEquals(5, result);
    }

}
```

Anatomi test:

```text
@Test                          → tandai method sebagai test case
assertEquals(expected, actual) → 5 (diharapkan) == 2+3 (aktual)?
```

Jalankan:

::tabs
::tabs-item{label="Windows"}
```powershell
.\mvnw.cmd test
```
::

::tabs-item{label="macOS / Linux"}
```bash
./mvnw test
```
::
::

Output yang diharapkan di akhir log:

```text
Tests run: 1, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

::tip
Kebiasaan yang sehat: test **harus** dilihat berjalan dan lulus dulu sebelum dipercaya. Test yang belum pernah gagal perlu dicurigai — coba sengaja ubah expected ke `6`, jalankan, lihat `BUILD FAILURE`, lalu kembalikan. Sekarang kita tahu persis seperti apa "test gagal itu terlihat".
::

## 3. Integration Test dengan `@SpringBootTest`

Test pertama tidak menyentuh Spring. Sekarang kita uji apakah **aplikasi utuh** bisa menyala — konteks Spring terbentuk, semua bean ter-wiring, konfigurasi terbaca.

### Ganti seluruh isi file test

```java
package com.example.belajarspringboot;

import org.junit.jupiter.api.Test;
import org.springframework.boot.test.context.SpringBootTest;

@SpringBootTest
class BelajarSpringBootApplicationTests {

    @Test
    void contextLoads() {
    }

}
```

Method-nya kosong — justru itu intinya. `@SpringBootTest` membuat seluruh `ApplicationContext` **sebelum test dijalankan**. Kalau ada bean yang gagal dibuat atau konfigurasi rusak, test gagal **sebelum** method dieksekusi.

```text
@SpringBootTest
      ↓
ApplicationContext dibuat (semua bean di-wiring)
      ↓
contextLoads() dijalankan → kosong → PASS
```

::alert{type="warning" icon="lucide:alert-triangle"}
`@SpringBootTest` memuat aplikasi **lengkap termasuk koneksi database**. Pastikan `docker compose up -d` berjalan saat mengeksekusi test — kalau MySQL tidak ada, test ini gagal (dan itu memang pesan yang benar: aplikasi yang butuh database tidak boleh dianggap "lulus test" tanpa database).
::

## 4. `MockMvc`: Menguji Endpoint Tanpa Server

Untuk menguji controller, kita tidak perlu aplikasi jalan di port 8080 + Postman. `MockMvc` mensimulasikan HTTP request langsung ke DispatcherServlet:

```text
Dengan Postman:                    Dengan MockMvc:
Postman → HTTP → Tomcat → ...      Test → MockMvc → DispatcherServlet → Controller
(butuh server hidup)               (tanpa server, cepat)
```

### Ganti seluruh isi file test

```java
package com.example.belajarspringboot;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.web.servlet.MockMvc;

@SpringBootTest
@AutoConfigureMockMvc
class BelajarSpringBootApplicationTests {

    @Autowired
    private MockMvc mockMvc;

    @Test
    void contextLoads() {
    }

    @Test
    void helloEndpointShouldReturn200() throws Exception {
        mockMvc.perform(get("/api/hello"))
                .andExpect(status().isOk());
    }

}
```

Membaca test-nya seperti kalimat:

```text
"lakukan GET /api/hello ... dan harapkan status 200 OK"
```

`@AutoConfigureMockMvc` menyediakan objek `MockMvc` yang siap pakai (di-`@Autowired` — DI bekerja juga di test).

## 5. Memeriksa Body JSON

Status `200` saja belum cukup — kita juga bisa memeriksa **isi respons**. Tambahkan test ini:

```java
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
// ... letakkan bersama import statis lainnya

@Test
void helloShouldReturnCorrectMessage() throws Exception {
    mockMvc.perform(get("/api/hello"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$").value("Halo dari Belajar Spring Boot"));
}
```

`jsonPath("$")` merujuk ke root respons; `jsonPath("$.message")` merujuk properti `message` bila responsnya objek JSON:

```json
{ "message": "..." }   →   jsonPath("$.message").value("...")
```

::alert{type="info" icon="lucide:info"}
Nilai yang diharapkan mengikuti `app.name` di konfigurasi — sebab `/api/hello` mengembalikan `"Halo dari " + appName` sejak [Bab 11](/spring-boot/konfigurasi-dan-lingkungan). Kalau respons kalian berbeda, sesuaikan stringnya; yang penting **asertif mencerminkan perilaku yang diharapkan**.
::

## 6. Menguji Validation dan Error Handling

Sekarang bagian paling berharga: test yang menjaga perilaku yang kita bangun di [Bab 10](/spring-boot/validation-dan-error-handling).

### Ganti seluruh isi file test (versi lengkap akhir)

```java
package com.example.belajarspringboot;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;

@SpringBootTest
@AutoConfigureMockMvc
class BelajarSpringBootApplicationTests {

    @Autowired
    private MockMvc mockMvc;

    @Test
    void contextLoads() {
    }

    @Test
    void helloEndpointShouldReturn200() throws Exception {
        mockMvc.perform(get("/api/hello"))
                .andExpect(status().isOk());
    }

    @Test
    void createUserWithInvalidDataShouldReturn400() throws Exception {
        String requestBody = """
                {
                    "name": "",
                    "email": "bukan-email"
                }
                """;

        mockMvc.perform(post("/api/users")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(requestBody))
                .andExpect(status().isBadRequest())
                .andExpect(jsonPath("$.errors.name").value("Nama tidak boleh kosong"))
                .andExpect(jsonPath("$.errors.email").value("Format email tidak valid"));
    }

    @Test
    void getUnknownUserShouldReturn404() throws Exception {
        mockMvc.perform(get("/api/users/99999999"))
                .andExpect(status().isNotFound())
                .andExpect(jsonPath("$.message").value(
                        "User dengan ID 99999999 tidak ditemukan"));
    }

}
```

Dua hal Java modern yang dipakai:

::tabs
::tabs-item{label="Text Block"}
```java
String requestBody = """
        {
            "name": "",
            "email": "bukan-email"
        }
        """;
```

Text block (Java 15+) menulis JSON multiline apa adanya — tanpa `\"` dan `\n` berantakan seperti string lama:
```java
String requestBody = "{\n    \"name\": \"\",\n    \"email\": \"bukan-email\"\n}";  // ✗ lama
```
::

::tabs-item{label="Method Reference & chaining"}
```java
.andExpect(status().isBadRequest())
.andExpect(jsonPath("$.errors.name").value("Nama tidak boleh kosong"))
```

Asertif bisa dirantai — tiap `.andExpect()` adalah satu pemeriksaan. Bila yang pertama gagal, sisanya tidak dieksekusi dan pesan kegagalannya menjelaskan apa yang beda.
::
::

## 7. Jalankan Semua Test

```bash
./mvnw test
```

```text
Tests run: 4, Failures: 0, Errors: 0, Skipped: 0
BUILD SUCCESS
```

Empat test, empat perilaku terjaga:

| Test | Menjaga |
| :--- | :--- |
| `contextLoads` | Aplikasi bisa menyala utuh |
| `helloEndpointShouldReturn200` | Endpoint hello hidup |
| `createUserWithInvalidDataShouldReturn400` | Validation + handler 400 |
| `getUnknownUserShouldReturn404` | Error handling 404 |

::alert{type="success" icon="lucide:check"}
Mulai sekarang, setiap kali mengubah kode: jalankan `./mvnw test`. Kalau suatu hari refactor merusak validasi, test akan **berteriak** — bukan user kita yang menemukannya.
::

## 8. Unit Test vs Integration Test

| | Unit Test | Integration Test |
| :--- | :--- | :--- |
| Cakupan | Satu class / method | Beberapa layer bekerja sama |
| Spring context | Tidak | Ya (`@SpringBootTest`) |
| Kecepatan | Sangat cepat | Lebih lambat |
| Contoh | `HelloService.calculateDiscount()` | `MockMvc` → Controller → Service → Repo |
| Bila rusak | Logika salah | Koneksi/wiring/layer salah |

Test-test kita di atas mayoritas **integration test**. Unit test ideal untuk logika bisnis murni — misalnya `calculateDiscount` bisa diuji tanpa Spring sama sekali:

```java
@Test
void discountShouldDeductTenPercent() {
    HelloService service = new HelloService();
    assertEquals(90000.0, service.calculateDiscount(100000.0));
}
```

Tidak ada annotation Spring, tidak ada context — cukup `new`. Kalau method-nya nanti punya dependency, barulah Mockito (di starter-test) bermain untuk membuat tiruannya.

## 9. Ke Mana Lanjut: Testcontainers

Database koneksi untuk integration test kita masih meminjam MySQL Docker development. Untuk proyek yang lebih serius, standar industri adalah **Testcontainers** — library yang otomatis menjalankan **container database baru khusus untuk test**, lalu membuangnya selesai:

```text
Testcontainers:
  ./mvnw test → Docker start MySQL ephemeral → test jalan → container dibuang
  → database test selalu bersih, tidak menyerang data development
```

Cukup ditambahkan sebagai dependency `org.testcontainers:mysql` — tidak ada konfigurasi rumit. Ini topik lanjutan yang sangat layak diambil setelah modul ini selesai.

## 10. Masalah Umum

::tabs
::tabs-item{label="Test gagal karena database"}
`@SpringBootTest` butuh koneksi MySQL. Jalankan `docker compose up -d` sebelum test. Pesan `Communications link failure` = container mati.
::

::tabs-item{label="Test 404 gagal"}
Test mengharapkan ID `99999999` tidak ada di database. Kalau suatu saat data test membuat ID besar itu (hampir mustahil), pakai ID lain yang jelas tidak ada.
::

::tabs-item{label="MockMvc null / unavailable"}
Pastikan class test ber-annotation `@SpringBootTest` **dan** `@AutoConfigureMockMvc` — dua-duanya. Salah satu hilang → `MockMvc` tidak disediakan.
::

::tabs-item{label="Test tidak ditemukan Maven"}
File test wajib di `src/test/java/` dan nama class diakhiri... tidak wajib, tapi konvensi `*Test` dipakai Maven Surefire secara default. Nama seperti `MyTests.java` tidak dijalankan otomatis.
::
::

## 11. Checklist

- [ ] Test pertama (tanpa Spring) lulus
- [ ] `contextLoads` lulus dengan database berjalan
- [ ] `MockMvc` berhasil menguji `GET /api/hello`
- [ ] Test validation memastikan `400` + detail error per-field
- [ ] Test 404 memastikan pesan error yang benar
- [ ] `./mvnw test` → `BUILD SUCCESS`
- [ ] Pahami beda unit test vs integration test
- [ ] Tahu bahwa Testcontainers adalah langkah lanjutan untuk database testing
