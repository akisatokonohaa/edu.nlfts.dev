CRUD kita sudah berjalan, tetapi masih **naif**. Coba kirim:

```json
{
  "name": "",
  "email": "bukan-email"
}
```

Aplikasi dengan senang hati menyimpannya. Dan `GET /api/users/999` masih membalas `500 Internal Server Error` padahal seharusnya `404 Not Found`. Bab ini menutup dua lubang itu: **validation** (jaga pintu masuk) dan **error handling** (respons saat masalah terjadi).

---

## 1. Validation vs Error Handling

Dua hal berbeda yang saling melengkapi:

| | Validation | Error Handling |
| :--- | :--- | :--- |
| Pertanyaannya | "Apakah input memenuhi aturan?" | "Bagaimana merespons masalah?" |
| Contoh | Email kosong → tolak | User tidak ada → 404 |
| Hasil gagal | `400 Bad Request` + detail kesalahan | Status + pesan yang tepat |

```text
Request → Validation → valid? ── ya → Service → Repository → Database
                            └─ tidak → 400 + detail error
```

Data yang sudah diketahui tidak valid **tidak pernah** meneruskan ke Service atau database.

---

## 2. Tambah Dependency Validation

Buka `pom.xml`, tambahkan:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

Starter ini membawa **Bean Validation** (spesifikasi Jakarta Validation + implementasi Hibernate Validator) — standar resmi validasi di ekosistem Jakarta.

## 3. Beri Aturan pada Entity

### Ganti bagian field pada `entity/User.java`

```java
package com.example.belajarspringboot.entity;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;
import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.NotBlank;

@Entity
@Table(name = "users")
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank(message = "Nama tidak boleh kosong")
    private String name;

    @NotBlank(message = "Email tidak boleh kosong")
    @Email(message = "Format email tidak valid")
    private String email;

    // ... constructor dan getter/setter tetap sama seperti sebelumnya

}
```

::tabs
::tabs-item{label="@NotBlank"}
Menolak `null`, string kosong `""`, dan string berisi spasi `"   "`.

```json
{ "name": "",  "email": "ehan@example.com" }   → ditolak
{ "name": "   ", "email": "ehan@example.com" } → ditolak
{ "name": "Rehan", "email": "..." }            → lolos
```
::

::tabs-item{label="@Email"}
Memeriksa format email.

```text
ehan@example.com   → lolos
ehan               → ditolak
ehan@example       → ditolak
```

Penting: `@Email` **tidak** mewajibkan terisi — `null` tetap lolos. Karena itu email kita beri **kedua** annotation: `@NotBlank` menjaga keberadaan, `@Email` menjaga format.
::

::tabs-item{label="Annotation validasi lain"}
Beberapa yang akan sering dipakai nanti:

| Annotation | Aturan |
| :--- | :--- |
| `@Size(min, max)` | Panjang string / ukuran koleksi |
| `@Min` / `@Max` | Rentang angka |
| `@Positive` / `@PositiveOrZero` | Angka positif |
| `@Past` / `@Future` | Rentang waktu (tanggal) |
| `@Pattern(regexp)` | Cocok dengan regex |
::
::

## 4. Aktifkan dengan `@Valid`

Annotation di Entity saja **belum menjalankan apa pun**. Kita harus memerintahkan Spring memeriksa objek request — lewat `@Valid` di Controller.

### Ganti seluruh isi `controller/UserController.java`

```java
package com.example.belajarspringboot.controller;

import com.example.belajarspringboot.entity.User;
import com.example.belajarspringboot.service.UserService;
import jakarta.validation.Valid;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/users")
public class UserController {

    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @PostMapping
    public ResponseEntity<User> createUser(@Valid @RequestBody User user) {
        User saved = userService.createUser(user);
        return ResponseEntity.status(201).body(saved);
    }

    @GetMapping
    public List<User> getAllUsers() {
        return userService.getAllUsers();
    }

    @GetMapping("/{id}")
    public ResponseEntity<User> getUserById(@PathVariable Long id) {
        return ResponseEntity.ok(userService.getUserById(id));
    }

    @PutMapping("/{id}")
    public ResponseEntity<User> updateUser(
            @PathVariable Long id,
            @Valid @RequestBody User user
    ) {
        return ResponseEntity.ok(userService.updateUser(id, user));
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteUser(@PathVariable Long id) {
        userService.deleteUser(id);
        return ResponseEntity.noContent().build();
    }

}
```

Perubahan: `@Valid` menempel pada `@RequestBody` di **POST dan PUT** (keduanya menerima data dari klien).

```text
@RequestBody  → "ubah JSON jadi object"
@Valid        → "periksa object itu terhadap annotation validasi"
```

Uji sekarang: kirim `{"name":"","email":"bukan-email"}` → ditolak dengan `400`. Tetapi responsenya masih panjang dan jelek (format default Spring). Bagian berikutnya merapikannya.

## 5. Custom Exception

Sekarang perbaiki `500` untuk "user tidak ditemukan". Ganti `RuntimeException` dengan exception yang **bermakna**.

### Buat file baru

```text
src/main/java/com/example/belajarspringboot/exception/ResourceNotFoundException.java
```

```java
package com.example.belajarspringboot.exception;

public class ResourceNotFoundException extends RuntimeException {

    public ResourceNotFoundException(String message) {
        super(message);
    }

}
```

### Ganti seluruh isi `service/UserService.java`

```java
package com.example.belajarspringboot.service;

import com.example.belajarspringboot.entity.User;
import com.example.belajarspringboot.exception.ResourceNotFoundException;
import com.example.belajarspringboot.repository.UserRepository;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class UserService {

    private final UserRepository userRepository;

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    public User createUser(User user) {
        if (userRepository.existsByEmail(user.getEmail())) {
            throw new IllegalStateException("Email sudah digunakan: " + user.getEmail());
        }
        return userRepository.save(user);
    }

    public List<User> getAllUsers() {
        return userRepository.findAll();
    }

    public User getUserById(Long id) {
        return userRepository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException(
                        "User dengan ID " + id + " tidak ditemukan"));
    }

    public User updateUser(Long id, User user) {
        User existingUser = getUserById(id);

        existingUser.setName(user.getName());
        existingUser.setEmail(user.getEmail());

        return userRepository.save(existingUser);
    }

    public void deleteUser(Long id) {
        if (!userRepository.existsById(id)) {
            throw new ResourceNotFoundException(
                    "User dengan ID " + id + " tidak ditemukan");
        }
        userRepository.deleteById(id);
    }

}
```

Perubahan penting:

1. `RuntimeException` → `ResourceNotFoundException` (makna jelas: 404-bound)
2. Email duplikat → `IllegalStateException` (pelanggaran aturan bisnis → 409-bound)
3. `updateUser` kini memanggil `getUserById(id)` — tidak ada duplikasi logika pencarian

Mengapa exception dilempar di **Service**? Karena "user tidak ada" adalah **aturan bisnis**. Controller tidak perlu tahu bagaimana "tidak ada" itu dideteksi — ia cukup menerima exception dan biarkan handler yang merespons.

## 6. Global Exception Handler

Bayangkan aplikasi punya 15 controller. Kalau tiap controller menulis `try-catch` untuk tiap kasus, kodenya hancur oleh pengulangan. Spring menyediakan **satu tempat** untuk menangani exception dari semua controller:

```text
UserController ─┐
ProductController ─┼──→ @RestControllerAdvice (satu tempat)
OrderController ─┘
```

### Buat file baru

```text
src/main/java/com/example/belajarspringboot/exception/GlobalExceptionHandler.java
```

```java
package com.example.belajarspringboot.exception;

import java.time.Instant;
import java.util.LinkedHashMap;
import java.util.Map;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<Map<String, Object>> handleNotFound(
            ResourceNotFoundException ex
    ) {
        return build(HttpStatus.NOT_FOUND, ex.getMessage(), null);
    }

    @ExceptionHandler(IllegalStateException.class)
    public ResponseEntity<Map<String, Object>> handleConflict(
            IllegalStateException ex
    ) {
        return build(HttpStatus.CONFLICT, ex.getMessage(), null);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, Object>> handleValidation(
            MethodArgumentNotValidException ex
    ) {
        Map<String, String> errors = new LinkedHashMap<>();

        ex.getBindingResult().getFieldErrors().forEach(error ->
                errors.put(error.getField(), error.getDefaultMessage()));

        return build(HttpStatus.BAD_REQUEST, "Validasi gagal", errors);
    }

    private ResponseEntity<Map<String, Object>> build(
            HttpStatus status, String message, Map<String, String> errors
    ) {
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("status", status.value());
        body.put("error", status.getReasonPhrase());
        body.put("message", message);
        body.put("timestamp", Instant.now().toString());
        if (errors != null) {
            body.put("errors", errors);
        }
        return ResponseEntity.status(status).body(body);
    }

}
```

### Bagaimana cara kerjanya

```text
Exception dilempar dari mana pun
      ↓
@RestControllerAdvice menangkapnya
      ↓
cari @ExceptionHandler yang tipe-nya cocok
      ↓
method menyusun response body
      ↓
HTTP status + JSON dikirim ke klien
```

Tiga pemetaan yang kita buat:

| Exception | Status | Skenario |
| :--- | :--- | :--- |
| `ResourceNotFoundException` | **404 Not Found** | User/ID tidak ada |
| `IllegalStateException` | **409 Conflict** | Email sudah dipakai |
| `MethodArgumentNotValidException` | **400 Bad Request** | Validation gagal |

## 7. Uji Ketiga Skenario

### 404 — resource tidak ada

```bash
curl http://localhost:8080/api/users/999
```

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "User dengan ID 999 tidak ditemukan",
  "timestamp": "2026-09-25T10:15:30Z"
}
```

### 409 — bisnis tertolak

Kirim POST dengan email yang sudah ada:

```json
{
  "status": 409,
  "error": "Conflict",
  "message": "Email sudah digunakan: rehan@example.com",
  "timestamp": "2026-09-25T10:16:10Z"
}
```

### 400 — validation gagal

```json
{
  "status": 400,
  "error": "Bad Request",
  "message": "Validasi gagal",
  "errors": {
    "name": "Nama tidak boleh kosong",
    "email": "Format email tidak valid"
  }
}
```

Klien sekarang menerima **detail persis field mana yang salah dan mengapa** — bukan halaman error rahasia yang membingungkan.

::alert{type="info" icon="lucide:info"}
Format respons error di atas adalah format buatan sendiri yang mudah dipahami. Menariknya, Spring Boot 6 (Framework 7) punya dukungan bawaan **RFC 9457 Problem Details** — standar industri untuk respons error HTTP — melalui property `spring.mvc.problemdetails.enabled=true`. Layak dieksplorasi setelah bab ini.
::

## 9. Masalah Umum

::tabs
::tabs-item{label="Import validation tidak ditemukan"}
`jakarta.validation.constraints.NotBlank` tidak ketemu → dependency `spring-boot-starter-validation` belum ditambahkan ke `pom.xml`.
::

::tabs-item{label="Validation tidak jalan"}
Tiga komponen wajib lengkap:

```text
1. starter-validation di pom.xml
2. annotation di field entity (@NotBlank, @Email)
3. @Valid di parameter controller
```

Hilang satu saja → validasi diam-diam tidak berjalan.
::

::tabs-item{label="404 masih berupa error default Spring"}
`GlobalExceptionHandler` belum terdeteksi. Pastikan: ada `@RestControllerAdvice`, dan package-nya di bawah root `com.example.belajarspringboot`.
::

::tabs-item{label="javax vs jakarta"}
Semua import validation harus `jakarta.validation.*`, bukan `javax.validation.*` — tutorial lama adalah sumber kebingungan ini.
::
::

## 10. Checklist

- [ ] `spring-boot-starter-validation` ditambahkan
- [ ] Entity punya `@NotBlank` dan `@Email` dengan pesan bahasa Indonesia
- [ ] `@Valid` terpasang pada POST dan PUT
- [ ] `ResourceNotFoundException` dibuat dan dipakai di Service
- [ ] `GlobalExceptionHandler` menangani 400 / 404 / 409
- [ ] `GET /api/users/999` → `404` dengan pesan jelas
- [ ] POST email duplikat → `409 Conflict`
- [ ] POST data kosong → `400` + detail per-field

## Ringkasan

```text
Validation           → @NotBlank/@Email di entity + @Valid di controller → 400
Custom exception     → ResourceNotFoundException, IllegalStateException
@RestControllerAdvice→ satu tempat menangani exception semua controller
Pemetaan             → 400 (input salah) / 404 (tidak ada) / 409 (konflik aturan)

API kita kini:
  - menolak data sampah sebelum menyentuh database
  - menjawab error dengan status + pesan yang benar
```

Tinggal satu fondasi: memisahkan konfigurasi dari kode agar aplikasi bisa berpindah environment tanpa diubah.
