Salah satu fitur inti dari Nuxt adalah *router* berbasis sistem file. Setiap file Vue yang ada di dalam [direktori `app/pages/`](/nuxt/directory-structure/app/pages) akan otomatis membuat URL (atau *route*) yang sesuai untuk menampilkan isi dari file tersebut. Dengan memanfaatkan *dynamic import* untuk setiap halaman, Nuxt mengoptimalkan *code-splitting* sehingga hanya mengirimkan jumlah JavaScript seminimal mungkin untuk *route* yang diminta.

::note
Fitur *code-splitting* ini aktif secara bawaan dan sangat kami sarankan untuk sebagian besar aplikasi. Kalau kamu punya alasan khusus untuk mengirim satu *bundle* saja alih-alih memecahnya, kamu bisa menonaktifkannya di [`nuxt.config`](/nuxt/api/nuxt-config)-mu:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  vite: {
    $client: {
      build: {
        rolldownOptions: {
          output: {
            codeSplitting: false,
          },
        },
      },
    },
  },
})
```

Cara ini akan menggabungkan semua JavaScript ke dalam satu file saja. Ini jarang sekali menguntungkan — biasanya justru akan menambah ukuran unduhan awal, bahkan di koneksi yang lambat — jadi pertimbangkan untuk mematikan *code-splitting* hanya kalau kamu sudah mengukur dan membuktikan bahwa itu memang membantu kasusmu.
::

## Halaman (*Pages*)

*Routing* di Nuxt dibangun di atas [vue-router](https://router.vuejs.org) dan membuat *route* dari setiap komponen yang kamu buat di [direktori `app/pages/`](/nuxt/directory-structure/app/pages), berdasarkan nama file-nya masing-masing.

Sistem *routing* ini memanfaatkan konvensi penamaan untuk membuat *route* yang dinamis maupun bersarang (*nested*):

::code-group

```bash [Struktur Direktori]
-| pages/
---| about.vue
---| index.vue
---| posts/
-----| [id].vue
```

```json [File Router yang Dihasilkan]
{
  "routes": [
    {
      "path": "/about",
      "component": "pages/about.vue"
    },
    {
      "path": "/",
      "component": "pages/index.vue"
    },
    {
      "path": "/posts/:id",
      "component": "pages/posts/[id].vue"
    }
  ]
}
```

::

## Navigasi

Komponen [`<NuxtLink>`](/nuxt/api/components/nuxt-link) berfungsi untuk menghubungkan satu halaman dengan halaman lainnya. Komponen ini akan me-*render* tag `<a>` dengan atribut `href` yang diatur menuju *route* halaman tujuan. Setelah aplikasi di-*hydrate*, transisi antar halaman akan dikerjakan oleh JavaScript dengan cara memperbarui URL peramban. Hal ini mencegah *refresh* halaman secara penuh dan memungkinkan adanya animasi transisi.

Ketika sebuah [`<NuxtLink>`](/nuxt/api/components/nuxt-link) masuk ke area layar (*viewport*) di sisi *client*, Nuxt akan secara otomatis melakukan *prefetch* terhadap komponen dan *payload* (halaman yang sudah dihasilkan) dari halaman yang ditautkan lebih awal. Hasilnya, navigasi terasa jauh lebih cepat.

```vue [app/pages/index.vue]
<template>
  <header>
    <nav>
      <ul>
        <li><NuxtLink to="/about">About</NuxtLink></li>
        <li><NuxtLink to="/posts/1">Post 1</NuxtLink></li>
        <li><NuxtLink to="/posts/2">Post 2</NuxtLink></li>
      </ul>
    </nav>
  </header>
</template>
```

:read-more{to="/nuxt/api/components/nuxt-link"}

## Parameter Route

Composable [`useRoute()`](/nuxt/api/composables/use-route) bisa kamu pakai di dalam blok `<script setup>` atau metode `setup()` pada komponen Vue untuk mengakses detail dari *route* yang sedang aktif.

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
const route = useRoute()

// Saat mengakses /posts/1, route.params.id akan bernilai 1
console.log(route.params.id)
</script>
```

:read-more{to="/nuxt/api/composables/use-route"}

## Route Middleware

Nuxt menyediakan kerangka *route middleware* yang bisa dikustomisasi dan kamu pakai di seluruh aplikasimu. Ini sangat ideal untuk memisahkan kode yang ingin kamu jalankan sebelum menavigasi ke *route* tertentu.

::note
*Route middleware* dijalankan di bagian Vue dari aplikasi Nuxt-mu. Meski namanya mirip, mereka ini totally berbeda dengan *server middleware*, yang mana dijalankan di bagian *server* Nitro milik aplikasimu.
::

::important
*Route middleware* **tidak** akan berjalan untuk *server route* (misalnya `/api/*`) atau *request* server lainnya. Untuk menerapkan *middleware* pada *request* tersebut, gunakanlah [*server middleware*](/nuxt/directory-structure/server#server-middleware).
::

Ada tiga jenis *route middleware*:

1. *Anonymous* (atau *inline*) *route middleware*, yang didefinisikan langsung di halaman tempat dia dipakai.
2. *Named route middleware*, yang ditempatkan di [direktori `app/middleware/`](/nuxt/directory-structure/app/middleware) dan akan secara otomatis dimuat lewat *asynchronous import* saat dipakai di suatu halaman. (**Catatan**: Nama *route middleware* akan dinormalisasi menjadi *kebab-case*, jadi `someMiddleware` akan berubah menjadi `some-middleware`.)
3. *Global route middleware*, yang ditempatkan di [direktori `app/middleware/`](/nuxt/directory-structure/app/middleware) (dengan akhiran `.global`) dan akan secara otomatis berjalan setiap kali ada perubahan *route*.

Berikut contoh *middleware* `auth` yang melindungi halaman `/dashboard`:

::code-group

```ts twoslash [middleware/auth.ts]
function isAuthenticated (): boolean { return false }
// ---cut---
export default defineNuxtRouteMiddleware((to, from) => {
  // isAuthenticated() adalah contoh metode untuk memverifikasi apakah pengguna sudah terautentikasi
  if (isAuthenticated() === false) {
    return navigateTo('/login')
  }
})
```

```vue twoslash [pages/dashboard.vue]
<script setup lang="ts">
definePageMeta({
  middleware: 'auth',
})
</script>

<template>
  <h1>Welcome to your dashboard</h1>
</template>
```

::

## Validasi Route

Nuxt menawarkan fitur validasi *route* melalui properti `validate` di dalam [`definePageMeta()`](/nuxt/api/utils/define-page-meta) pada setiap halaman yang ingin kamu validasi.

Properti `validate` ini menerima `route` sebagai argumennya. Kamu bisa mengembalikan nilai *boolean* untuk menentukan apakah *route* ini valid untuk di-*render* dengan halaman tersebut atau tidak. Kalau kamu mengembalikan `false`, maka akan memicu error 404. Kamu juga bisa langsung mengembalikan sebuah objek yang berisi `status`/`statusText` untuk mengkustomisasi error yang dikembalikan.

Kalau kamu punya kasus yang lebih kompleks, kamu bisa memakai *anonymous route middleware* sebagai gantinya.

```vue twoslash [pages/posts/[id\\].vue]
<script setup lang="ts">
definePageMeta({
  validate (route) {
    // Periksa apakah id terdiri dari angka
    return typeof route.params.id === 'string' && /^\d+$/.test(route.params.id)
  },
})
</script>
```
