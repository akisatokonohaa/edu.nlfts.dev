Aplikasi Nuxt bisa di-*deploy* di server Node.js, di-*pre-render* untuk *hosting* statis, atau di-*deploy* ke lingkungan *serverless* maupun *edge* (CDN).

::tip
Kalau kamu sedang mencari daftar penyedia *cloud* yang mendukung Nuxt, cek bagian [Penyedia Hosting](/deploy).
::

## Server Node.js

Temukan *preset* server Node.js dengan Nitro untuk melakukan *deploy* di *hosting* Node apa pun.

- **Format *output* bawaan** kalau tidak ada yang ditentukan atau terdeteksi otomatis <br>
- Hanya memuat *chunk* yang dibutuhkan untuk me-*render* *request* agar waktu *cold start* optimal <br>
- Berguna untuk melakukan *deploy* aplikasi Nuxt ke *hosting* Node.js mana pun

### Titik Masuk (*Entry Point*)

Saat menjalankan `nuxt build` dengan *preset* server Node, hasilnya akan berupa titik masuk yang menjalankan server Node yang siap pakai (*ready-to-run*).

```bash [Terminal]
NODE_ENV=production node .output/server/index.mjs
```

Ini akan menjalankan server Nuxt produksimu yang secara bawaan mendengarkan di port 3000.

::important
Atur `NODE_ENV=production` saat menjalankan server. Beberapa *dependency* (terutama Vue Router) hanya akan menghilangkan peringatan khusus pengembangan saat ini diatur, jadi membiarkannya tanpa pengaturan bisa membanjiri *log*-mu dengan pesan seperti `[Vue Router warn]: No match found for location with path …` pada *route* yang tidak cocok.
::

Ini mengikuti variabel lingkungan *runtime* berikut:

- `NITRO_PORT` atau `PORT` (bawaannya `3000`)
- `NITRO_HOST` atau `HOST` (bawaannya `'0.0.0.0'`)
- `NITRO_SSL_CERT` dan `NITRO_SSL_KEY` - kalau keduanya ada, ini akan menjalankan server dalam mode HTTPS. Dalam mayoritas besar kasus, ini sebaiknya tidak digunakan selain untuk pengujian, dan server Nitro sebaiknya dijalankan di balik *reverse proxy* seperti nginx atau Cloudflare yang menangani SSL.

### Menyajikan Build yang Sama di Beberapa Path (*Serving the Same Build at Multiple Paths*)

Untuk *deployment subpath* normal, atur [`app.baseURL`](/nuxt/api/nuxt-config#baseurl) atau variabel lingkungan `NUXT_APP_BASE_URL`.

Kalau *reverse proxy* dengan sengaja mengekspos halaman yang sama di beberapa *path* publik, Nuxt bisa mengganti URL peramban dengan *path* yang dipakai untuk *server rendering* selama proses *hydration*. Kamu bisa mempertahankan URL peramban dengan menghapus *path* yang di-*render* dari *payload* di *plugin* server:

```ts [app/plugins/preserve-proxy-url.server.ts]
export default defineNuxtPlugin((nuxtApp) => {
  delete nuxtApp.payload.path
})
```

Gunakan ini hanya kalau *proxy* sudah menangani aset dan *routing* untuk setiap *path* publik. Tanpa *path* yang di-*render*, Nuxt tidak bisa memperbaiki ketidakcocokan yang nyata antara URL yang diminta dengan *route* yang di-*render* server.

### PM2

[PM2](https://pm2.keymetrics.io/) (*Process Manager 2*) adalah solusi yang cepat dan mudah untuk *hosting* aplikasi Nuxt-mu di server atau VM-mu.

Untuk memakai `pm2`, gunakan `ecosystem.config.cjs`:

```ts [ecosystem.config.cjs]
module.exports = {
  apps: [
    {
      name: 'NuxtAppName',
      port: '3000',
      exec_mode: 'cluster',
      instances: 'max',
      script: './.output/server/index.mjs',
      env: {
        NODE_ENV: 'production',
      },
    },
  ],
}
```

### Mode *Cluster*

Kamu bisa menggunakan `NITRO_PRESET=node_cluster` untuk memanfaatkan performa multi-proses menggunakan modul [cluster](https://nodejs.org/dist/latest/docs/api/cluster.html) milik Node.js.

Secara bawaan, *workload* didistribusikan ke *worker* dengan strategi *round robin*.

## Hosting Statis

Ada dua cara untuk melakukan *deployment* aplikasi Nuxt ke layanan *hosting* statis apa pun:

- *Static site generation* (SSG) dengan `ssr: true` akan melakukan *pre-render* pada *route* aplikasimu pada saat *build*. (Ini adalah perilaku bawaan saat menjalankan `nuxt generate`.) Ini juga akan menghasilkan halaman *fallback single-page app* `/200.html` dan `/404.html`, yang bisa me-*render* *route* dinamis atau *error* 404 di sisi *client* (meskipun kamu mungkin perlu mengonfigurasi ini di *host* statismu). Lihat [Apa itu 200.html dan 404.html?](/nuxt/guide/concepts/rendering#what-are-200html-and-404html).
- Sebagai alternatif, kamu bisa melakukan *prerender* situsmu dengan `ssr: false` (*single-page app* statis). Ini akan menghasilkan halaman HTML dengan `<div id="__nuxt"></div>` kosong di mana aplikasi Vue-mu seharusnya di-*render*. Kamu akan kehilangan banyak manfaat SEO dari *prerendering* situsmu, jadi sebagai gantinya disarankan untuk menggunakan [`<ClientOnly>`](/nuxt/api/components/client-only) untuk membungkus bagian dari situsmu yang tidak bisa di-*render* di sisi server (kalau ada).

*Route* yang di-*prerender* juga akan memancarkan file `_payload.json` berisi data yang ditangkap pada saat *build*, yang akan digunakan ulang oleh Nuxt selama navigasi sisi *client*. Baca selengkapnya tentang [ekstraksi *payload*](/nuxt/getting-started/prerendering#payload-extraction).

### Halaman *Fallback* Statis

Nuxt bisa menghasilkan dua halaman *fallback* untuk *host* statis:

- `200.html` adalah *fallback single-page app*. Konfigurasi *host*-mu untuk menyajikannya pada *route* yang tidak cocok saat kamu ingin *routing* sisi *client* yang menangani URL tersebut.
- `404.html` adalah *fallback* tidak-ditemukan. Konfigurasi *host*-mu untuk menyajikannya pada *route* yang harus mempertahankan *status* 404.

`nuxt generate` dan `nuxt build --prerender` akan menghasilkan file-file ini secara otomatis. Kalau kamu menggunakan `nuxt build` dengan *route rules* untuk melakukan *prerender* pada *route* yang dipilih, tambahkan halaman *fallback* ini secara eksplisit:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/200.html': { prerender: true },
  },
})
```

Secara bawaan, kedua *fallback* ini hanyalah *shell* kosong. Atur [`experimental.prerenderErrorPages`](/nuxt/guide/concepts/rendering#server-rendering-the-error-page) untuk me-*render* `error.vue`-mu ke dalam `404.html` pada saat *build*.

Beberapa penyedia menggunakan `200.html`, beberapa menggunakan `404.html`, dan beberapa membiarkan kamu mengonfigurasi keduanya. Periksa pengaturan *fallback* atau *rewrite* statis dari penyedia *hosting*-mu setelah *deployment*.

:read-more{title="Prerendering Nuxt" to="/nuxt/getting-started/prerendering"}

### Rendering Hanya di Sisi Client (*Client-side Only Rendering*)

Kalau kamu tidak ingin melakukan *prerender* pada *route*-mu, cara lain menggunakan *hosting* statis adalah dengan mengatur properti `ssr` ke `false` di file `nuxt.config`. Perintah `nuxt generate` selanjutnya akan menghasilkan titik masuk `.output/public/index.html` dan *bundle* JavaScript seperti aplikasi Vue.js sisi *client* klasik.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  ssr: false,
})
```

## Preset

Selain server Node.js dan layanan *hosting* statis, proyek Nuxt bisa di-*deploy* dengan beberapa *preset* yang sudah teruji baik dengan jumlah konfigurasi yang sangat minim.

Kamu bisa menetapkan *preset* yang diinginkan secara eksplisit di file [`nuxt.config.ts`](/nuxt/directory-structure/nuxt-config):

```ts twoslash [nuxt.config.ts]
// @errors: 2353
export default defineNuxtConfig({
  nitro: {
    preset: 'node-server',
  },
})
```

... atau gunakan variabel lingkungan `NITRO_PRESET` saat menjalankan `nuxt build`:

```bash [Terminal]
NITRO_PRESET=node-server nuxt build
```

🔎 Cek [*deployment Nitro*](https://nitro.build/deploy) untuk semua *preset* dan penyedia *deployment* yang tersedia.

## Proxy CDN

Di sebagian besar kasus, Nuxt bisa bekerja dengan konten pihak ketiga yang tidak dibuat atau dihasilkan oleh Nuxt itu sendiri. Tapi terkadang konten seperti itu bisa menimbulkan masalah, terutama opsi "Minification and Security Options" milik Cloudflare.

Oleh karena itu, kamu harus memastikan opsi-opsi berikut dicentang / dinonaktifkan di Cloudflare. Kalau tidak, *re-rendering* yang tidak perlu atau *error hydration* bisa memberikan dampak buruk pada aplikasi produksimu.

1. `Speed > Settings > Content Optimization > Nonaktifkan "Rocket Loader™"`
2. `Security > Settings > Nonaktifkan "Email Address Obfuscation"`

Dengan pengaturan ini, kamu bisa memastikan bahwa Cloudflare tidak akan menyuntikkan *script* ke dalam aplikasi Nuxt-mu yang bisa menyebabkan *side effect* yang tidak diinginkan.

::tip
Lokasinya di *dashboard* Cloudflare kadang berpindah, jangan ragu untuk mencarinya.
