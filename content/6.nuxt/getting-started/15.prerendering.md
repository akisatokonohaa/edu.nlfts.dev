Nuxt memungkinkan halaman-halaman pilihan dari aplikasimu untuk di-*render* pada saat *build*. Nuxt akan menyajikan halaman yang sudah dibangun sebelumnya saat diminta, alih-alih membuatnya secara langsung (*on the fly*).

:read-more{title="Mode rendering Nuxt" to="/nuxt/guide/concepts/rendering"}

## Prerendering Berbasis Crawling (*Crawl-based Pre-rendering*)

Gunakan [perintah `nuxt generate`](/nuxt/api/commands/generate) untuk membangun dan melakukan *prerender* pada aplikasimu menggunakan *crawler* [Nitro](/nuxt/guide/concepts/server-engine). Perintah ini mirip dengan `nuxt build` dengan opsi `nitro.static` diatur ke `true`, atau menjalankan `nuxt build --prerender`.

Ini akan membangun situsmu, membangun *instance* nuxt, dan secara bawaan melakukan *prerender* pada halaman root `/` beserta halaman situsmu mana pun yang ditautkan di dalamnya, halaman situsmu mana pun yang ditautkan oleh halaman tersebut, dan seterusnya.

::code-group{sync="pm"}

```bash [npm]
npx nuxt generate
```

```bash [yarn]
yarn nuxt generate
```

```bash [pnpm]
pnpm nuxt generate
```

```bash [bun]
bun x nuxt generate
```

```bash [deno]
deno x nuxt generate
```

::

Sekarang kamu bisa melakukan *deploy* direktori `.output/public` ke layanan *hosting* statis apa pun atau mem-*preview* secara lokal dengan `npx serve .output/public`.

*Build* statis dan *prerender* juga akan memancarkan *fallback* SPA `200.html` dan `404.html`. Lihat [Apa itu 200.html dan 404.html?](/nuxt/guide/concepts/rendering#what-are-200html-and-404html).

Cara kerja *crawler* Nitro:

1. Memuat HTML dari *route* root aplikasimu (`/`), halaman non-dinamis apa pun di direktori `~/pages`-mu, dan *route* lainnya dalam *array* `nitro.prerender.routes`.
2. Menyimpan HTML dan `_payload.json` ke direktori `~/.output/public/` untuk disajikan secara statis.
3. Menemukan semua *anchor tag* (`<a href="...">`) di dalam HTML untuk menavigasi ke *route* lain.
4. Mengulangi langkah 1-3 untuk setiap *anchor tag* yang ditemukan sampai tidak ada lagi *anchor tag* yang bisa di-*crawl*.

Ini penting untuk dipahami karena halaman yang tidak ditautkan ke halaman yang bisa ditemukan tidak bisa di-*prerender* secara otomatis.

:read-more{to="/nuxt/api/commands/generate#nuxt-generate"}
Baca selengkapnya tentang perintah `nuxt generate`.
::

### Prerendering Selektif

Kamu bisa menentukan *route* secara manual yang akan diambil dan di-*prerender* oleh [Nitro](/nuxt/guide/concepts/server-engine) selama *build*, atau mengabaikan *route* yang tidak ingin kamu *prerender* seperti `/dynamic` di file `nuxt.config`:

```ts twoslash [nuxt.config.ts]
// @errors: 2353
export default defineNuxtConfig({
  nitro: {
    prerender: {
      routes: ['/user/1', '/user/2'],
      ignore: ['/dynamic'],
    },
  },
})
```

Kamu bisa menggabungkan ini dengan opsi `crawlLinks` untuk melakukan *prerender* pada sekumpulan *route* yang tidak bisa ditemukan oleh *crawler* seperti `/sitemap.xml` atau `/robots.txt`-mu:

```ts twoslash [nuxt.config.ts]
// @errors: 2353
export default defineNuxtConfig({
  nitro: {
    prerender: {
      crawlLinks: true,
      routes: ['/sitemap.xml', '/robots.txt'],
    },
  },
})
```

Mengatur `nitro.prerender` ke `true` itu sama saja seperti mengatur `nitro.prerender.crawlLinks` ke `true`.

:read-more{to="https://nitro.build/config#prerender"}
Baca selengkapnya tentang *prerendering* di dokumentasi Nitro.
::

Terakhir, kamu bisa mengaturnya secara manual menggunakan *routeRules*.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    // Atur prerender ke true untuk mengonfigurasinya agar di-prerender
    '/rss.xml': { prerender: true },
    // Atur ke false untuk melewatinya dari proses prerendering
    '/this-DOES-NOT-get-prerendered': { prerender: false },
    // Semua yang ada di bawah /blog akan di-prerender selama
    // ditautkan dari halaman lain
    '/blog/**': { prerender: true },
  },
})
```

:read-more{to="https://nitro.build/config#routerules"}
Baca selengkapnya tentang konfigurasi `routeRules` milik Nitro.
::

Sebagai jalan pintas, kamu juga bisa mengaturnya di file halaman menggunakan [`defineRouteRules`](/nuxt/api/utils/define-route-rules).

:read-more{to="/nuxt/guide/going-further/experimental-features#inlinerouterules" icon="i-lucide-star"}
Fitur ini eksperimental dan agar bisa menggunakannya kamu harus mengaktifkan opsi `experimental.inlineRouteRules` di `nuxt.config`-mu.
::

```vue [app/pages/index.vue]
<script setup>
// Atau atur di level halaman
defineRouteRules({
  prerender: true,
})
</script>

<template>
  <div>
    <h1>Homepage</h1>
    <p>Di-prerender pada saat build</p>
  </div>
</template>
```

Ini akan diterjemahkan menjadi:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/': { prerender: true },
  },
})
```

## Ekstraksi Payload

Saat Nuxt me-*render* halaman di server, ia menserialisasi hasil pengambilan datamu ([`useAsyncData`](/nuxt/api/composables/use-async-data) dan [`useFetch`](/nuxt/api/composables/use-fetch)) serta *state* aplikasi ([`useState`](/nuxt/api/composables/use-state)) menjadi *payload* agar *client* bisa me-*hydrate* tanpa mengambil ulang data. Dengan ekstraksi *payload* yang diaktifkan, Nuxt juga menulis *payload* ini ke file `_payload.json` berdampingan HTML *route* tersebut:

- *Route* yang di-*prerender* membuat file *payload*-nya pada saat *build*.
- *Route* yang memakai *caching* [ISR atau SWR](/nuxt/guide/concepts/rendering#hybrid-rendering) membuat file *payload*-nya saat *route* tersebut pertama kali di-*render*, bahkan di situs hibrida (non-statis).

Selama navigasi sisi *client*, Nuxt mengambil file `_payload.json` untuk *route* tujuan dan menggunakan kembali data yang diekstrak alih-alih menjalankan pengambilan data lagi di peramban.

Kamu bisa mengontrol perilaku ini dengan opsi [`experimental.payloadExtraction`](/nuxt/api/nuxt-config#payloadextraction):

- `'client'` - *Payload* di-*inline* di HTML untuk *render* awal dan diekstrak ke file `_payload.json` untuk navigasi sisi *client*. Tidak ada *network request* ekstra saat pemuatan pertama.
- `true` - *Payload* diekstrak ke file `_payload.json` terpisah baik untuk *render* awal maupun navigasi sisi *client*. HTML-nya jadi lebih kecil dan file *payload*-nya bisa di-*cache* oleh CDN, dengan konsekuensi satu *request* ekstra saat pemuatan pertama.
- `false` - Ekstraksi *payload* dinonaktifkan. *Payload* selalu di-*inline* di dalam HTML dan tidak ada file `_payload.json` yang dihasilkan.

Nilai bawaannya adalah `true`, atau `'client'` kalau `compatibilityVersion: 5` diatur. Nilai ini dipaksa menjadi `false` kalau `ssr: false` diatur.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    payloadExtraction: 'client',
  },
})
```

Beberapa konsekuensi praktis yang perlu kamu ketahui:

- Di situs yang sepenuhnya statis, navigasi sisi *client* menggunakan ulang data yang ditangkap pada saat *build*, jadi data bisa sudah tidak mutakhir (*stale*) sampai *build* berikutnya.
- Untuk *route* ISR/SWR, CDN bisa men-*cache* file *payload* berdampingan HTML, meningkatkan performa navigasi sisi *client* untuk *route* yang di-*cache*. *Route* dinamis seperti `pages/[...slug].vue` bisa mengikutinya dengan pola *glob* seperti `'/**': { isr: true }`.
- *Payload* diserialisasi dengan [devalue](https://github.com/Rich-Harris/devalue), jadi tipe kustom (seperti *instance class*) membutuhkan *plugin payload* dengan *reducer* dan *reviver* kustom agar bisa bertahan dalam perjalanan pulang-pergi (*round trip*).

:read-more{title="Reducer dan reviver payload" to="/nuxt/api/composables/use-nuxt-app#payload"}

## Konfigurasi Prerender saat Runtime

### `prerenderRoutes`

Kamu bisa menggunakan ini saat *runtime* di dalam [konteks Nuxt](/nuxt/guide/going-further/nuxt-app#the-nuxt-context) untuk menambahkan *route* lain agar di-*prerender* oleh Nitro.

```vue [app/pages/index.vue]
<script setup>
prerenderRoutes(['/some/other/url'])
prerenderRoutes('/api/content/article/my-article')
</script>

<template>
  <div>
    <h1>Ini akan mendaftarkan route lain untuk di-prerender saat proses prerender</h1>
  </div>
</template>
```

:read-more{title="prerenderRoutes" to="/nuxt/api/utils/prerender-routes"}

### *Hook* Nuxt `prerender:routes`

Ini dipanggil sebelum *prerendering* untuk mendaftarkan *route* tambahan.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  hooks: {
    async 'prerender:routes' (ctx) {
      const { pages } = await fetch('https://api.some-cms.com/pages').then(
        res => res.json(),
      )
      for (const page of pages) {
        ctx.routes.add(`/${page.name}`)
      }
    },
  },
})
```

### *Hook* Nitro `prerender:generate`

Ini dipanggil untuk setiap *route* selama proses *prerendering*. Kamu bisa memakai ini untuk penanganan yang lebih detail (*fine-grained*) pada setiap *route* yang di-*prerender*.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  nitro: {
    hooks: {
      'prerender:generate' (route) {
        if (route.route?.includes('private')) {
          route.skip = true
        }
      },
    },
  },
})
```
