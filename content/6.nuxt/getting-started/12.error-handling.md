Nuxt adalah *framework* *full-stack*, yang berarti ada beberapa sumber *error runtime* pengguna yang tidak bisa dicegah dan bisa terjadi di berbagai konteks:

- *Error* selama siklus hidup *rendering* Vue (SSR & CSR)
- *Error* saat *startup* server dan klien (SSR + CSR)
- *Error* selama siklus hidup *server* Nitro ([direktori `server/`](/nuxt/directory-structure/server))
- *Error* saat mengunduh *JS chunk*

::tip
**SSR** adalah singkatan dari **Server-Side Rendering** dan **CSR** dari **Client-Side Rendering**.
::

## Error Vue

Kamu bisa menyadap (*hook*) *error* Vue menggunakan [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured).

Selain itu, Nuxt menyediakan *hook* [`vue:error`](/nuxt/api/advanced/hooks#app-hooks-runtime) yang akan dipanggil kalau ada *error* yang merambat (*propagate*) hingga ke level paling atas.

Kalau kamu memakai *framework* pelaporan *error*, kamu bisa menyediakan *handler* global melalui [`vueApp.config.errorHandler`](https://vuejs.org/api/application#app-config-errorhandler). Ini akan menerima semua *error* Vue, bahkan jika mereka sudah ditangani.

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.vueApp.config.errorHandler = (error, instance, info) => {
    // tangani error, misalnya laporkan ke sebuah layanan
  }

  // Bisa juga dilakukan seperti ini
  nuxtApp.hook('vue:error', (error, instance, info) => {
    // tangani error, misalnya laporkan ke sebuah layanan
  })
})
```

::note
Perhatikan bahwa *hook* `vue:error` dibangun berdasarkan *lifecycle hook* [`onErrorCaptured`](https://vuejs.org/api/composition-api-lifecycle#onerrorcaptured).
::

## Error Startup

Nuxt akan memanggil *hook* `app:error` kalau ada *error* saat memulai aplikasi Nuxt-mu.

Ini termasuk:
- menjalankan [plugin Nuxt](/nuxt/directory-structure/app/plugins)
- memproses *hook* `app:created` dan `app:beforeMount`
- me-*render* aplikasi Vue-mu ke HTML (saat SSR)
- melakukan *mount* aplikasi (di sisi *client*), meskipun sebaiknya kasus ini kamu tangani dengan `onErrorCaptured` atau dengan `vue:error`
- memproses *hook* `app:mounted`

## Error Server Nitro

Saat ini kamu belum bisa mendefinisikan *handler* sisi *server* untuk *error* ini, tapi kamu bisa me-*render* halaman *error*, lihat bagian [Me-*render* Halaman Error](/nuxt/getting-started/error-handling#error-page).

## Error pada JS Chunks

Kamu mungkin akan menemui *error* saat memuat *chunk* karena kegagalan koneksi jaringan atau *deployment* baru (yang membatalkan URL *JS chunk* lama yang sudah di-*hash*). Nuxt menyediakan dukungan bawaan untuk menangani *error* pemuatan *chunk* dengan melakukan *hard reload* saat sebuah *chunk* gagal dimuat selama navigasi *route*.

Kamu bisa mengubah perilaku ini dengan mengatur `experimental.emitRouteChunkError` ke `false` (untuk menonaktifkan *hook* ke *error* ini sama sekali) atau ke `manual` kalau kamu ingin menanganinya sendiri. Kalau kamu ingin menangani *error* pemuatan *chunk* secara manual, kamu bisa melihat [implementasi otomatisnya](https://github.com/nuxt/nuxt/blob/main/packages/nuxt/src/app/plugins/chunk-reload.client.ts) untuk mendapat ide.

## Halaman Error

::note
Saat Nuxt menemui *error fatal* (sebarang *error* yang tidak ditangani di *server*, atau *error* yang dibuat dengan `fatal: true` di *client*), ia akan me-*render* respons JSON (kalau diminta dengan *header* `Accept: application/json`) atau memicu halaman *error* *full-screen*.
::

*Error* bisa terjadi selama siklus hidup *server* saat:
- memproses plugin Nuxt-mu
- me-*render* aplikasi Vue-mu ke dalam HTML
- *route* API *server* melempar *error*

Ini juga bisa terjadi di sisi *client* saat:
- memproses plugin Nuxt-mu
- sebelum melakukan *mount* aplikasi (*hook* `app:beforeMount`)
- melakukan *mount* aplikasimu kalau *error*-nya tidak ditangani dengan *hook* `onErrorCaptured` atau `vue:error`
- aplikasi Vue diinisialisasi dan di-*mount* di peramban (`app:mounted`).

::read-more{to="/nuxt/api/advanced/hooks"}
Temukan semua *lifecycle hook* Nuxt.
::

Kustomisasi halaman *error* bawaan dengan menambahkan `~/error.vue` di direktori sumber aplikasimu, berdampingan dengan `app.vue`.

<!-- TODO:twoslash: Twoslash does not support tsconfig paths yet -->

```vue [error.vue]
<script setup lang="ts">
import type { NuxtError } from '#app'

const props = defineProps({
  error: Object as () => NuxtError,
})

const handleError = () => clearError({ redirect: '/' })
</script>

<template>
  <div>
    <h2>{{ error?.status }}</h2>
    <button @click="handleError">
      Clear errors
    </button>
  </div>
</template>
```

::read-more{to="/nuxt/directory-structure/app/error"}
Baca selengkapnya tentang `error.vue` dan penggunaannya.
::

Untuk *error* kustom, kami sangat menyarankan untuk menggunakan *composable* `onErrorCaptured` yang bisa dipanggil di fungsi *setup* halaman/komponen, atau *hook* *runtime* nuxt `vue:error` yang bisa dikonfigurasi di *plugin* nuxt.

```ts twoslash [plugins/error-handler.ts]
export default defineNuxtPlugin((nuxtApp) => {
  nuxtApp.hook('vue:error', (err) => {
    //
  })
})
```

Kalau kamu sudah siap untuk menghapus halaman *error*, kamu bisa memanggil fungsi pembantu [`clearError`](/nuxt/api/utils/clear-error), yang menerima *path* opsional untuk dijadikan *redirect* (misalnya, kalau kamu ingin menavigasi ke halaman yang 'aman').

::important
Pastikan untuk memeriksa sebelum menggunakan apa pun yang bergantung pada *plugin* Nuxt, seperti `$route` atau `useRouter`, karena kalau sebuah *plugin* melempar *error*, maka *plugin* tersebut tidak akan dijalankan ulang sampai kamu menghapus *error*-nya.
::

::note
Me-*render* halaman *error* adalah *page load* yang sepenuhnya terpisah, yang berarti *middleware* yang terdaftar akan berjalan lagi. Kamu bisa memakai [`useError`](/nuxt/getting-started/error-handling#useerror) di *middleware* untuk mengecek apakah sebuah *error* sedang ditangani.
::

::note
Kalau kamu menjalankan di Node 16 dan kamu menetapkan *cookie* apa pun saat me-*render* halaman *error*-mu, *cookie* tersebut akan [menimpa *cookie* yang sebelumnya sudah ditetapkan](https://github.com/nuxt/nuxt/pull/20585). Kami menyarankan untuk menggunakan versi Node yang lebih baru karena Node 16 sudah mencapai akhir masa pakainya (*end-of-life*) pada September 2023.
::

## Utilitas Error

### `useError`

```ts [TS Signature]
function useError (): Ref<Error | { url, status, statusText, message, description, data }>
```

Fungsi ini akan mengembalikan *error* Nuxt global yang sedang ditangani.

::read-more{to="/nuxt/api/composables/use-error"}
Baca selengkapnya tentang *composable* `useError`.
::

### `createError`

```ts [TS Signature]
function createError (err: string | { cause, data, message, name, stack, status, statusText, fatal }): Error
```

Buat objek *error* dengan *metadata* tambahan. Kamu bisa memberikan *string* untuk diatur sebagai `message` *error* atau sebuah objek yang berisi properti *error*. Ini bisa dipakai di bagian Vue maupun Server dari aplikasimu, dan memang dimaksudkan untuk dilempar (*thrown*).

Kalau kamu melempar *error* yang dibuat dengan `createError`:
- di sisi *server*, ini akan memicu halaman *error* *full-screen* yang bisa kamu hapus dengan [`clearError`](/nuxt/getting-started/error-handling#clearerror).
- di sisi *client*, ini akan melempar *error* non-*fatal* untuk kamu tangani. Kalau kamu perlu memicu halaman *error* *full-screen*, kamu bisa melakukannya dengan mengatur `fatal: true`.

Di mode pengembangan, `cause` dari *error* akan dipertahankan dan ditampilkan di halaman *error*-mu sehingga kamu bisa melacak *error* aslinya; di produksi, *cause* tidak pernah disertakan di respons *error* atau *payload* halaman *error*.

```vue twoslash [pages/movies/[slug\\].vue]
<script setup lang="ts">
const route = useRoute()
const { data } = await useFetch(`/api/movies/${route.params.slug}`)

if (!data.value) {
  throw createError({
    status: 404,
    statusText: 'Page Not Found',
  })
}
</script>
```

::tip
Properti `statusText` dimaksudkan untuk teks *status* yang singkat dan sesuai standar HTTP (misalnya, "Not Found"). Properti ini sebaiknya hanya berisi tab horizontal, spasi, dan karakter ASCII yang terlihat (`[\t\u0020-\u007E]`). Untuk deskripsi detail, pesan multi-baris, atau konten dengan karakter non-ASCII, kamu harus selalu menggunakan properti `message` sebagai gantinya.
::

::read-more{to="/nuxt/api/utils/create-error"}
Baca selengkapnya tentang utilitas `createError`.
::

### `showError`

```ts [TS Signature]
function showError (err: string | Error | { status, statusText }): Error
```

Kamu bisa memanggil fungsi ini kapan saja di sisi *client*, atau (di sisi *server*) langsung di dalam *middleware*, *plugin*, atau fungsi `setup()`. Ini akan memicu halaman *error* *full-screen* yang bisa kamu hapus dengan [`clearError`](/nuxt/getting-started/error-handling#clearerror).

Sebagai gantinya, lebih direkomendasikan untuk menggunakan `throw createError()`.

::read-more{to="/nuxt/api/utils/show-error"}
Baca selengkapnya tentang utilitas `showError`.
::

### `clearError`

```ts [TS Signature]
function clearError (options?: { redirect?: string }): Promise<void>
```

Fungsi ini akan menghapus *error* Nuxt yang sedang ditangani saat ini. Fungsi ini juga menerima *path* opsional untuk dijadikan *redirect* (misalnya, kalau kamu ingin menavigasi ke halaman yang 'aman').

## Render Error di Komponen

Nuxt juga menyediakan komponen [`<NuxtErrorBoundary>`](/nuxt/api/components/nuxt-error-boundary) yang memungkinkanmu menangani *error* sisi *client* di dalam aplikasimu, tanpa mengganti seluruh situsmu dengan halaman *error*.

Komponen ini bertanggung jawab untuk menangani *error* yang terjadi di dalam *slot default*-nya. Di sisi *client*, ini akan mencegah *error* merambat ke level atas, dan sebagai gantinya akan me-*render* *slot* `#error`.

*Slot* `#error` akan menerima `error` sebagai *prop*. (Kalau kamu mengatur `error = null` itu akan memicu *render ulang* *slot default*; kamu harus memastikan bahwa *error* sudah terselesaikan sepenuhnya terlebih dahulu atau *slot error* hanya akan di-*render* untuk kedua kalinya.)

::tip
Kalau kamu menavigasi ke *route* lain, *error* akan dihapus secara otomatis.
::

```vue [app/pages/index.vue]
<template>
  <!-- beberapa konten -->
  <NuxtErrorBoundary @error="someErrorLogger">
    <!-- Kamu menggunakan slot default untuk merender kontenmu -->
    <template #error="{ error, clearError }">
      Kamu bisa menampilkan error secara lokal di sini: {{ error }}
      <button @click="clearError">
        Ini akan menghapus error.
      </button>
    </template>
  </NuxtErrorBoundary>
</template>
```
