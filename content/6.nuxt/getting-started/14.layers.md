Salah satu fitur inti dari Nuxt adalah dukungan untuk *layers* dan perluasan (*extending*). Kamu bisa memperluas aplikasi Nuxt bawaan untuk menggunakan ulang komponen, utilitas, dan konfigurasi. Struktur *layers* ini hampir identik dengan aplikasi Nuxt standar, yang membuatnya mudah untuk dibuat dan dipelihara.

## Kasus Penggunaan (*Use Cases*)

- Membagikan *preset* konfigurasi yang bisa dipakai ulang di berbagai proyek menggunakan `nuxt.config` dan `app.config`
- Membuat *library* komponen menggunakan [direktori `app/components/`](/nuxt/directory-structure/app/components)
- Membuat *library* utilitas dan *composable* menggunakan [direktori `app/composables/`](/nuxt/directory-structure/app/composables) dan [direktori `app/utils/`](/nuxt/directory-structure/app/utils)
- Membuat *preset* modul Nuxt
- Membagikan *setup* standar di berbagai proyek
- Membuat tema Nuxt
- Meningkatkan organisasi kode dengan menerapkan arsitektur modular dan mendukung pola *Domain-Driven Design* (DDD) dalam proyek berskala besar.

## Penggunaan

Secara bawaan, *layer* apa pun di dalam proyekmu yang berada di direktori `~~/layers` akan otomatis terdaftar sebagai *layer* di proyekmu.

::note
*Auto-registration* *layer* diperkenalkan di Nuxt v3.12.0.
::

Selain itu, *alias layer* yang bernama menuju *srcDir* dari masing-masing *layer* ini juga akan otomatis dibuat. Misalnya, kamu bisa mengakses *layer* `~~/layers/test` melalui `#layers/test`.

::note
*Alias layer* bernama diperkenalkan di Nuxt v3.16.0.
::

Selain itu, kamu bisa memperluas dari sebuah *layer* dengan menambahkan properti [extends](/nuxt/api/nuxt-config#extends) ke file [`nuxt.config`](/nuxt/directory-structure/nuxt-config)-mu.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // Perluas dari layer lokal
    '../base',
    // Perluas dari paket npm yang terinstal
    '@my-themes/awesome',
    // Perluas dari repositori git
    'github:my-themes/awesome#v1',
  ],
})
```

Kamu juga bisa memberikan *token* autentikasi kalau kamu memperluas dari repositori GitHub pribadi:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    // konfigurasi per layer
    ['github:my-themes/private-awesome', { auth: process.env.GITHUB_TOKEN }],
  ],
})
```

::note
Kalau *branch* tidak ditentukan, ini akan meng-*clone* `main`.
::

::tip
Kamu bisa menimpa *alias* sebuah *layer* dengan menentukannya di opsi di samping sumber *layer* tersebut.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    [
      'github:my-themes/awesome',
      {
        meta: {
          name: 'my-awesome-theme',
        },
      },
    ],
  ],
})
```

::

Nuxt memakai [unjs/c12](https://github.com/unjs/c12) dan [unjs/giget](https://github.com/unjs/giget) untuk memperluas *layer* jarak jauh (*remote layers*). Cek dokumentasinya untuk informasi lebih lanjut dan semua opsi yang tersedia.

## Prioritas Layer

Saat menggunakan beberapa *layer*, penting untuk memahami urutan penimpaan (*override*). *Layer* dengan **prioritas lebih tinggi** akan menimpa *layer* dengan prioritas lebih rendah saat keduanya mendefinisikan file atau komponen yang sama.

### Urutan Prioritas

Dari prioritas tertinggi ke terendah:

1. **File proyekmu** - selalu memiliki prioritas tertinggi
2. **Layer yang di-*auto-scan* dari direktori `~~/layers`** - diurutkan berdasarkan abjad (Z memiliki prioritas lebih tinggi daripada A)
3. **Layer di konfigurasi `extends`** - entri pertama memiliki prioritas lebih tinggi daripada yang kedua

### Contoh Praktis

Bayangkan ada beberapa *layer* yang mendefinisikan komponen yang sama:

```bash [Struktur direktori]
layers/
  1.base/
    app/components/Button.vue    # Gaya tombol dasar
  2.theme/
    app/components/Button.vue    # Tombol bertema (menimpa dasar)
app/
  components/Button.vue          # Tombol proyek (menimpa semua layer)
```

Dalam kasus ini:
- Kalau hanya *layer* yang ada, `2.theme/Button.vue` yang akan dipakai (lebih tinggi secara abjad)
- Kalau `app/components/Button.vue` ada di proyekmu, itu akan menimpa semua *layer*

### Mengontrol Prioritas

Kamu bisa memberikan awalan angka pada direktori *layer* untuk mengontrol urutannya:

```bash [Struktur direktori]
layers/
  1.base/        # Prioritas terendah
  2.features/    # Prioritas menengah
  3.admin/       # Prioritas tertinggi (di antara layer)
```

::tip
Pola ini berguna untuk membuat *base layer* dengan *default* yang bisa secara bertahap ditimpa oleh *layer* yang lebih spesifik.
::

Sebagai alternatif, kamu bisa mengontrol urutan direktori `~~/layers`-mu dari `nuxt.config` dengan merujuknya di [`extends`](/nuxt/api/nuxt-config#extends), tanpa mengubah nama direktorimu. Entri-entri tersebut diurutkan seperti *layer* `extends` lainnya, di mana **entri pertama memiliki prioritas tertinggi**:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '~~/layers/admin', // prioritas tertinggi
    '~~/layers/features',
    '~~/layers/base', // prioritas terendah (di antara layer yang didaftar)
  ],
})
```

Baik bentuk *alias* `~~/...` (yang direkomendasikan) maupun `~/...`, serta *path* relatif (`./layers/admin`) semuanya didukung. *Layer* apa pun di `~~/layers` yang tidak kamu sebutkan akan mempertahankan urutan *auto-scan* abjadnya, dan diperingkatkan di bawah *layer* yang kamu sebutkan di `extends`.

### Kapan Menggunakan Masing-masing

- **Direktori `~~/layers`** - Gunakan untuk *layer* lokal yang merupakan bagian dari proyekmu
- **`extends`** - Gunakan untuk *dependensi* eksternal (*paket* npm, *repositori* jarak jauh) atau *layer* di luar direktori proyekmu

### Contoh Lengkap dengan `extends`

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: [
    '../base', // Layer lokal di luar proyek
    '@my-themes/awesome', // Paket NPM
    'github:my-themes/awesome#v1', // Repositori jarak jauh
  ],
})
```

Kalau kamu juga memiliki `~~/layers/custom`, urutan prioritasnya adalah:
- File proyekmu (tertinggi)
- `~~/layers/custom`
- `../base`
- `@my-themes/awesome`
- `github:my-themes/awesome#v1` (terendah)
