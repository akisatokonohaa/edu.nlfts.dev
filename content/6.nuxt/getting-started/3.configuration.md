Secara bawaan, Nuxt sudah menangani hampir semua kebutuhan umummu. Kalau kamu perlu mengubah atau menambahkan konfigurasi tersebut, kamu bisa melakukannya lewat file [`nuxt.config.ts`](/nuxt/directory-structure/nuxt-config).

## Konfigurasi Nuxt

File [`nuxt.config.ts`](/nuxt/directory-structure/nuxt-config) ini ditempatkan di akar (root) direktori proyek Nuxt-mu. Fungsinya tidak lain adalah untuk mengubah atau memperluas perilaku aplikasi.

Bentuk paling sederhana dari file ini adalah mengekspor fungsi `defineNuxtConfig` yang di dalamnya berisi objek konfigurasimu. Kamu tidak perlu repot-repot melakukan *import* karena *helper* `defineNuxtConfig` ini sudah tersedia secara global.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  // Konfigurasi Nuxt-ku
})
```

Nanti di dokumentasi ini, aku akan sering menyebut file ini. Misalnya, saat kita mau menambahkan *script* kustom, mendaftarkan modul, atau mengubah mode *rendering*.

::read-more{to="/nuxt/api/configuration/nuxt-config"}
Setiap opsi sudah dijelaskan secara lengkap di **Referensi Konfigurasi**.
::

::note
Sebenarnya, kamu tidak diwajibkan memakai TypeScript untuk membangun aplikasi dengan Nuxt. Tapi, aku sangat menyarankan agar kamu tetap menggunakan ekstensi `.ts` pada file `nuxt.config` ini. Dengan begitu, kamu bisa mendapat petunjuk (*hint*) langsung di IDE-mu, yang sangat membantu menghindari kesalahan ketik atau salah konfigurasi saat mengedit.
::

### Penggantian Berdasarkan Lingkungan (*Environment Overrides*)

Kamu bisa menyiapkan konfigurasi pengganti yang sudah sepenuhnya bertipe (*fully typed*) untuk tiap-tiap lingkungan (*environment*) di dalam `nuxt.config`-mu.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  $production: {
    routeRules: {
      '/**': { isr: true },
    },
  },
  $development: {
    //
  },
  $env: {
    staging: {
      //
    },
  },
})
```

Cara memilih lingkungan saat menjalankan perintah Nuxt CLI itu gampang, kamu tinggal sertakan nama lingkungannya pada flag `--envName`, seperti ini: `nuxt build --envName staging`.

Kalau kamu penasaran dengan mekanisme di balik fitur penggantian ini, aku sarankan untuk membaca dokumentasi `c12` mengenai [konfigurasi berbasis lingkungan (*environment-specific configuration*)](https://github.com/unjs/c12?tab=readme-ov-file#environment-specific-configuration).

:video-accordion{title="Tonton video dari Alexander Lichter tentang nuxt.config.ts yang sadar lingkungan (env-aware)" videoId="DFZI2iVCrNc"}

::note
Kalau kamu sedang membuat *layer*, kamu juga bisa memanfaatkan kunci `$meta` untuk menyediakan *metadata* yang bisa dipakai olehmu sendiri atau oleh konsumen *layer*-mu nanti.
::

### Variabel Lingkungan dan *Token* Privat

API `runtimeConfig` berfungsi untuk mengekspos nilai-nilai, seperti variabel lingkungan, ke seluruh bagian aplikasimu. Secara bawaan, kunci-kunci ini hanya bisa diakses dari sisi *server*. Namun, kunci yang berada di dalam `runtimeConfig.public` dan `runtimeConfig.app` (yang memang dipakai secara internal oleh Nuxt) juga bisa diakses dari sisi *client*.

Nilai-nilai tersebut sebaiknya didefinisikan di `nuxt.config` dan bisa kamu timpa (*override*) memakai variabel lingkungan.

::code-group

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    // Kunci privat yang hanya tersedia di sisi server
    apiSecret: '123',
    // Kunci di dalam 'public' juga akan terekspos ke sisi client
    public: {
      apiBase: '/api',
    },
  },
})
```

```ini [.env]
# Ini akan menimpa nilai dari apiSecret
NUXT_API_SECRET=api_secret_token
```

::

Nanti, variabel-variabel ini bisa kamu akses di seluruh aplikasimu menggunakan composable [`useRuntimeConfig()`](/nuxt/api/composables/use-runtime-config).

```vue [app/pages/index.vue]
<script setup lang="ts">
const runtimeConfig = useRuntimeConfig()
</script>
```

## Konfigurasi Aplikasi (*App Configuration*)

File `app.config.ts` yang berada di direktori sumber (secara bawaan ada di folder `app/`) dipakai untuk mengekspos variabel publik yang nilainya sudah ditentukan pada saat *build*. Berbeda dengan opsi `runtimeConfig`, variabel di sini tidak bisa ditimpa memakai variabel lingkungan.

Sama seperti sebelumnya, file konfigurasi minimalnya cukup mengekspor fungsi `defineAppConfig` yang berisi objek konfigurasimu. *Helper* `defineAppConfig` juga sudah tersedia secara global tanpa perlu di-*import*.

```ts [app/app.config.ts]
export default defineAppConfig({
  title: 'Hello Nuxt',
  theme: {
    dark: true,
    colors: {
      primary: '#ff0000',
    },
  },
})
```

Untuk mengakses variabel-variabel ini di bagian lain dari aplikasimu, kamu bisa memakai composable [`useAppConfig`](/nuxt/api/composables/use-app-config).

```vue [app/pages/index.vue]
<script setup lang="ts">
const appConfig = useAppConfig()
</script>
```

:read-more{to="/nuxt/directory-structure/app/app-config"}

## `runtimeConfig` vs. `app.config`

Seperti yang sudah aku jelaskan di atas, `runtimeConfig` dan `app.config` sama-sama berfungsi mengekspos variabel ke aplikasimu. Supaya kamu tidak bingung menentukan kapan harus memakai yang mana, ini panduan singkatnya:

- `runtimeConfig`: *Token* privat maupun publik yang nilainya baru bisa ditentukan setelah proses *build* menggunakan variabel lingkungan.
- `app.config`: *Token* publik yang sudah ditentukan saat *build*, konfigurasi situs web seperti variasi tema, judul, dan berbagai konfigurasi proyek lainnya yang bersifat tidak sensitif.

| Fitur                         | `runtimeConfig` | `app.config` |
|-------------------------------|-----------------|--------------|
| Sisi *client*                 | Di-*hydrate*    | Di-*bundle*  |
| Variabel lingkungan           | ✅ Ya           | ❌ Tidak     |
| Reaktif                       | ✅ Ya           | ✅ Ya        |
| Dukungan *Type*               | ✅ Parsial      | ✅ Ya        |
| Konfigurasi per *request*     | ❌ Tidak        | ✅ Ya        |
| *Hot Module Replacement*      | ❌ Tidak        | ✅ Ya        |
| Tipe JS non-primitif          | ❌ Tidak        | ✅ Ya        |

## File Konfigurasi Eksternal

Nuxt menjadikan file [`nuxt.config.ts`](/nuxt/directory-structure/nuxt-config) sebagai satu-satunya sumber kebenaran (*single source of truth*) untuk konfigurasi, dan tidak membaca file konfigurasi eksternal. Namun, selama membangun proyek, mungkin saja kamu perlu mengonfigurasi alat-alat eksternal tersebut. Tabel berikut menunjukkan konfigurasi umum dan bagaimana cara mengaturnya langsung lewat Nuxt.

| Nama                              | File Konfigurasi         | Cara Mengonfigurasi                                                        |
|-----------------------------------|--------------------------|----------------------------------------------------------------------------|
| [Nitro](https://nitro.build)      | `nitro.config.ts`   | Gunakan kunci [`nitro`](/nuxt/api/nuxt-config#nitro) di `nuxt.config` |
| [PostCSS](https://postcss.org)    | `postcss.config.js` | Gunakan kunci [`postcss`](/nuxt/api/nuxt-config#postcss) di `nuxt.config` |
| [Vite](https://vite.dev)          | `vite.config.ts`    | Gunakan kunci [`vite`](/nuxt/api/nuxt-config#vite) di `nuxt.config`   |
| [webpack](https://webpack.js.org) | `webpack.config.ts` | Gunakan kunci [`webpack`](/nuxt/api/nuxt-config#webpack-1) di `nuxt.config` |

Ini dia daftar file konfigurasi lainnya yang juga sering dipakai:

| Nama                                         | File Konfigurasi       | Cara Mengonfigurasi                                                              |

## Konfigurasi Vue

### Menggunakan Vite

Kalau kamu perlu memberikan opsi khusus ke `@vitejs/plugin-vue` atau `@vitejs/plugin-vue-jsx`, kamu bisa melakukannya langsung di file `nuxt.config`.

- `vite.vue` untuk `@vitejs/plugin-vue`. Cek [opsi yang tersedia](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue).
- `vite.vueJsx` untuk `@vitejs/plugin-vue-jsx`. Cek [opsi yang tersedia](https://github.com/vitejs/vite-plugin-vue/tree/main/packages/plugin-vue-jsx).

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vite: {
    vue: {
      customElement: true,
    },
    vueJsx: {
      mergeProps: true,
    },
  },
})
```

:read-more{to="/nuxt/api/configuration/nuxt-config#vue"}

### Menggunakan Webpack

Bagi kamu pengguna webpack yang perlu mengonfigurasi `vue-loader`, cara melakukannya adalah dengan memakai kunci `webpack.loaders.vue` di dalam file `nuxt.config`. Opsi-opsi yang bisa dipakai sudah kami definisikan di [sini](https://github.com/vuejs/vue-loader/blob/main/src/index.ts#L32-L62).

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  webpack: {
    loaders: {
      vue: {
        hotReload: true,
      },
    },
  },
})
```

:read-more{to="/nuxt/api/configuration/nuxt-config#loaders"}

### Mengaktifkan Fitur Eksperimental Vue

Terkadang kamu mungkin perlu mengaktifkan fitur eksperimental dari Vue, misalnya `propsDestructure`. Nuxt menyediakan cara yang sangat mudah untuk melakukannya di `nuxt.config.ts`, dan ini berlaku tidak peduli kamu pakai *builder* apa:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  vue: {
    propsDestructure: true,
  },
})
```

#### Migrasi `reactivityTransform` Eksperimental dari Vue 3.4 dan Nuxt 3.9

Sejak Nuxt 3.9 dan Vue 3.4, fitur `reactivityTransform` sudah dipindahkan dari Vue ke Vue Macros yang memiliki [integrasi Nuxt](https://vue-macros.dev/guide/nuxt-integration.html) sendiri.
