Nuxt menyediakan *composable* [`useState`](/nuxt/api/composables/use-state) untuk membuat *shared state* yang reaktif dan ramah SSR di seluruh komponen.

[`useState`](/nuxt/api/composables/use-state) adalah pengganti [`ref`](https://vuejs.org/api/reactivity-core#ref) yang ramah SSR. Nilainya akan dipertahankan setelah *server-side rendering* (saat proses *client-side hydration*) dan dibagikan ke semua komponen menggunakan kunci unik.

:video-accordion{title="Tonton video dari Alexander Lichter tentang alasan dan kapan harus menggunakan useState" videoId="mv0WcBABcIk"}

::important
Karena data di dalam [`useState`](/nuxt/api/composables/use-state) akan diserialisasi menjadi JSON, sangat penting untuk tidak menyematkan apa pun yang tidak bisa diserialisasi, seperti *class*, fungsi, atau *symbol*.
::

::read-more{to="/nuxt/api/composables/use-state"}
Baca selengkapnya tentang *composable* `useState`.
::

## Praktik Terbaik (*Best Practices*)

::warning
Jangan pernah mendefinisikan `const state = ref()` di luar `<script setup>` atau fungsi `setup()`. Misalnya, melakukan `export myState = ref({})` akan mengakibatkan *state* terbagi di seluruh *request* di server dan bisa menyebabkan *memory leak*.
::

::tip{icon="i-lucide-circle-check"}
Sebagai gantinya, gunakan `const useX = () => useState('x')`
::

## Contoh

### Penggunaan Dasar

Pada contoh ini, kami menggunakan *state* penghitung (*counter*) yang bersifat lokal komponen. Komponen lain apa pun yang memakai `useState('counter')` akan berbagi *state* reaktif yang sama.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const counter = useState('counter', () => Math.round(Math.random() * 1000))
</script>

<template>
  <div>
    Counter: {{ counter }}
    <button @click="counter++">
      +
    </button>
    <button @click="counter--">
      -
    </button>
  </div>
</template>
```

:link-example{to="/nuxt/examples/features/state-management"}

::note
Untuk menghapus (*invalidate*) *cached state* secara global, lihat utilitas [`clearNuxtState`](/nuxt/api/utils/clear-nuxt-state).
::

### Menginisialisasi State

Sebagian besar waktu, kamu akan ingin menginisialisasi *state*-mu dengan data yang diselesaikan secara *asynchronous*. Kamu bisa memakai komponen [`app.vue`](/nuxt/directory-structure/app/app) bersama utilitas [`callOnce`](/nuxt/api/utils/call-once) untuk melakukannya.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const websiteConfig = useState('config')

await callOnce(async () => {
  websiteConfig.value = await $fetch('https://my-cms.com/api/website-config')
})
</script>
```

::tip
Ini mirip dengan aksi [`nuxtServerInit`](https://v2.nuxt.com/docs/directory-structure/store/#the-nuxtserverinit-action) di Nuxt 2, yang memungkinkan mengisi *state* awal *store*-mu di sisi server sebelum halaman di-*render*.
::

:read-more{to="/nuxt/api/utils/call-once"}

### Penggunaan dengan Pinia

Pada contoh ini, kami memanfaatkan [modul Pinia](/modules/pinia) untuk membuat *global store* dan menggunakannya di seluruh aplikasi.

::important
Pastikan kamu sudah menginstal modul Pinia dengan `npx nuxt module add pinia` atau ikuti [langkah instalasi modulnya](https://pinia.vuejs.org/ssr/nuxt.html#Installation).
::

::code-group
```ts [app/stores/website.ts]
export const useWebsiteStore = defineStore('websiteStore', {
  state: () => ({
    name: '',
    description: '',
  }),
  actions: {
    async fetch () {
      const infos = await $fetch('https://api.nuxt.com/modules/pinia')

      this.name = infos.name
      this.description = infos.description
    },
  },
})
```
```vue [app/app.vue]
<script setup lang="ts">
const website = useWebsiteStore()

await callOnce(website.fetch)
</script>

<template>
  <main>
    <h1>{{ website.name }}</h1>
    <p>{{ website.description }}</p>
  </main>
</template>
```
::

## Penggunaan Lanjutan

::code-group
```ts [app/composables/locale.ts]
import type { Ref } from 'vue'

export const useLocale = () => {
  return useState<string>('locale', () => useDefaultLocale().value)
}

export const useDefaultLocale = (fallback = 'en-US') => {
  const locale = ref(fallback)
  if (import.meta.server) {
    const reqLocale = useRequestHeaders()['accept-language']?.split(',')[0]
    if (reqLocale) {
      locale.value = reqLocale
    }
  } else if (import.meta.client) {
    const navLang = navigator.language
    if (navLang) {
      locale.value = navLang
    }
  }
  return locale
}

export const useLocales = () => {
  const locale = useLocale()
  const locales = ref([
    'en-US',
    'en-GB',
    // ...,
    'ja-JP-u-ca-japanese',
  ])
  if (!locales.value.includes(locale.value)) {
    locales.value.unshift(locale.value)
  }
  return locales
}

export const useLocaleDate = (date: Ref<Date> | Date, locale = useLocale()) => {
  return computed(() => new Intl.DateTimeFormat(locale.value, { dateStyle: 'full' }).format(unref(date)))
}
```

```vue [app/app.vue]
<script setup lang="ts">
const locales = useLocales()
const locale = useLocale()
const date = useLocaleDate(new Date('2016-10-26'))
</script>

<template>
  <div>
    <h1>Nuxt birthday</h1>
    <p>{{ date }}</p>
    <label for="locale-chooser">Preview a different locale</label>
    <select
      id="locale-chooser"
      v-model="locale"
    >
      <option
        v-for="loc of locales"
        :key="loc"
        :value="loc"
      >
        {{ loc }}
      </option>
    </select>
  </div>
</template>
```
::

## Shared State

Dengan memanfaatkan [*composable* yang di-*auto-import*](/nuxt/directory-structure/app/composables), kita bisa mendefinisikan *state* global yang *type-safe* dan mengimpornya ke seluruh aplikasi.

```ts twoslash [composables/states.ts]
export const useColor = () => useState<string>('color', () => 'pink')
```

```vue [app/app.vue]
<script setup lang="ts">
// ---cut-start---
const useColor = () => useState<string>('color', () => 'pink')
// ---cut-end---
const color = useColor() // Sama seperti useState('color')
</script>

<template>
  <p>Current color: {{ color }}</p>
</template>
```

## Menggunakan Library Pihak Ketiga

Nuxt **dulu mengandalkan** *library* Vuex untuk menyediakan manajemen *state* global. Kalau kamu sedang bermigrasi dari Nuxt 2, silakan menuju [panduan migrasinya](/nuxt/migration/configuration#vuex).

Nuxt tidak memaksakan satu cara tertentu soal manajemen *state*, jadi silakan pilih solusi yang tepat untuk kebutuhanmu. Ada banyak integrasi dengan *library* manajemen *state* yang paling populer, termasuk:

- [Pinia](/modules/pinia) - rekomendasi resmi dari Vue
- [Harlem](/modules/harlem) - manajemen *state* global yang *immutable*
- [XState](/modules/xstate) - pendekatan *state machine* dengan alat untuk memvisualisasikan dan menguji logika *state*-mu
