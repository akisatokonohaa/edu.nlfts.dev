Nuxt hadir dengan dua *composable* dan satu *library* bawaan untuk melakukan pengambilan data di lingkungan peramban maupun server: `useFetch`, [`useAsyncData`](/nuxt/api/composables/use-async-data), dan `$fetch`.

Singkatnya:

- [`$fetch`](/nuxt/api/utils/dollarfetch) adalah cara paling sederhana untuk membuat *network request*.
- [`useFetch`](/nuxt/api/composables/use-fetch) adalah *wrapper* di sekitar `$fetch` yang mengambil data hanya sekali di [*universal rendering*](/nuxt/guide/concepts/rendering#universal-rendering).
- [`useAsyncData`](/nuxt/api/composables/use-async-data) mirip dengan `useFetch` tapi menawarkan kendali yang lebih detail.

Baik `useFetch` dan `useAsyncData` berbagi sekumpulan opsi dan pola umum yang akan aku jelaskan di bagian akhir nanti.

## Kebutuhan akan `useFetch` dan `useAsyncData`

Nuxt adalah *framework* yang bisa menjalankan kode isomorfik (atau *universal*) di lingkungan server dan *client*. Kalau [fungsi `$fetch`](/nuxt/api/utils/dollarfetch) dipakai untuk mengambil data di fungsi *setup* komponen Vue, hal ini bisa menyebabkan data diambil dua kali: sekali di server (untuk me-*render* HTML) dan sekali lagi di *client* (saat HTML di-*hydrate*). Ini bisa memicu masalah *hydration*, menambah waktu hingga siap interaksi, dan menyebabkan perilaku yang tidak terduga.

*Composable* [`useFetch`](/nuxt/api/composables/use-fetch) dan [`useAsyncData`](/nuxt/api/composables/use-async-data) menyelesaikan masalah ini dengan memastikan kalau panggilan API dilakukan di server, maka data tersebut akan diteruskan ke *client* di dalam *payload*.

*Payload* itu sendiri adalah objek JavaScript yang bisa diakses melalui [`useNuxtApp().payload`](/nuxt/api/composables/use-nuxt-app#payload). Ia digunakan di sisi *client* untuk menghindari pengambilan ulang data yang sama saat kode dieksekusi di peramban [saat proses *hydration*](/nuxt/guide/concepts/rendering#universal-rendering).

::tip
Gunakan [Nuxt DevTools](https://devtools.nuxt.com) untuk memeriksa data ini di tab **Payload**.
::

```vue [app/app.vue]
<script setup lang="ts">
const { data } = await useFetch('/api/data')

async function handleFormSubmit () {
  const res = await $fetch('/api/submit', {
    method: 'POST',
    body: {
      // Data form-ku
    },
  })
}
</script>

<template>
  <div v-if="data == undefined">
    No data
  </div>
  <div v-else>
    <form @submit="handleFormSubmit">
      <!-- tag input form -->
    </form>
  </div>
</template>
```

Pada contoh di atas, `useFetch` akan memastikan bahwa *request* terjadi di server dan diteruskan dengan benar ke peramban. `$fetch` tidak memiliki mekanisme seperti itu dan merupakan pilihan yang lebih tepat kalau *request*-nya memang hanya dilakukan dari peramban saja.

### Suspense

Di balik layar, Nuxt memakai komponen [`<Suspense>`](https://vuejs.org/guide/built-ins/suspense) milik Vue untuk mencegah navigasi sebelum semua data *asynchronous* tersedia untuk ditampilkan (di *view*). *Composable* pengambilan data bisa membantumu memanfaatkan fitur ini dan memilih apa yang paling cocok untuk setiap pemanggilan.

::note
Kamu bisa menambahkan [`<NuxtLoadingIndicator>`](/nuxt/api/components/nuxt-loading-indicator) untuk menampilkan *progress bar* di antara navigasi halaman.
::

### Catatan tentang `await`

Contoh-contoh di dokumentasi ini biasanya menggunakan `await` saat memanggil `useFetch` dan `useAsyncData`, tapi sebenarnya tidak selalu wajib begitu.

`await` **tidak** mengubah HTML yang di-*render* server. Saat proses *server rendering*, Nuxt akan menunggu *request* selesai sebelum menserialisasi halaman bagaimanapun caranya (memakai `<Suspense>` dan `onServerPrefetch` di balik layar), jadi hasil yang sudah terisi penuh akan selalu dikirim ke peramban.

Yang `await` *ubah* adalah apa yang terjadi selanjutnya di `<script setup>`-mu sendiri, dan bagaimana perilaku navigasi sisi *client*:

- **Dengan `await`**, eksekusi akan dijeda sampai data siap, jadi kode apa pun setelah pemanggilan itu bisa bergantung pada `data` yang sudah terisi. Pada navigasi sisi *client*, ini akan memblokir navigasi sampai data selesai: pengguna tetap di halaman saat ini (opsional dengan [`<NuxtLoadingIndicator>`](/nuxt/api/components/nuxt-loading-indicator)) lalu mendarat di halaman yang datanya sudah lengkap. Ini adalah perilaku bawaan.
- **Tanpa `await`**, eksekusi langsung dilanjutkan sementara *request* berjalan di latar belakang, jadi `data` akan memulai dari nilai *default*-nya dan terisi begitu *request* selesai. Pada navigasi sisi *client*, ini berarti navigasi terjadi langsung dan kamu bertanggung jawab untuk menangani kondisi *loading* dan *error*, biasanya lewat *ref* `status` dan `error` yang dikembalikan.

Tidak ada pendekatan yang secara universal lebih baik; pilihan yang tepat tergantung pada pengalaman yang kamu inginkan untuk *route* tersebut.

Tidak menggunakan *await* memiliki efek yang terlihat serupa oleh pengguna dengan opsi [`lazy`](#lazy) (navigasi tidak diblokir dan kamu menangani kondisi *loading* sendiri), tapi keduanya tidak identik: `lazy` adalah *flag* eksplisit yang menunda *request* sampai komponen di-*mount*, sedangkan tidak memakai *await* langsung memulai *request* saat *setup*. Lebih baik pakai `lazy` (atau [`useLazyFetch`](/nuxt/api/composables/use-lazy-fetch) / [`useLazyAsyncData`](/nuxt/api/composables/use-lazy-async-data)) kalau kamu ingin perilaku non-*blocking*, karena ini membuat niatmu lebih jelas.

::warning
`await` dan `lazy` itu independen, dan di sisi *client*, melakukan *await* pada fungsi `lazy` tidak akan memberikan efek yang kamu harapkan. Kalau kamu melakukan *await* pada pemanggilan `lazy` (misalnya `await useLazyFetch(...)` atau `await useFetch(..., { lazy: true })`), ini tetap memblokir *server rendering* seperti biasa, tapi pada **navigasi sisi *client*** `await`-nya akan langsung selesai tanpa menunggu *request*. `data` akan tetap bernilai *default* tepat setelah `await`, dan kamu harus menangani kondisi *loading* lewat `status`. Kalau kamu benar-benar ingin navigasi menunggu datanya, hapus opsi `lazy`-nya daripada mengandalkan `await`.
::

## `$fetch`

Nuxt menyertakan *library* [ofetch](https://github.com/unjs/ofetch) dan secara otomatis di-*import* sebagai alias `$fetch` secara global di seluruh aplikasimu.

```vue twoslash [pages/todos.vue]
<script setup lang="ts">
async function addTodo () {
  const todo = await $fetch('/api/todos', {
    method: 'POST',
    body: {
      // Data todo-ku
    },
  })
}
</script>
```

::warning
Perhatikan bahwa menggunakan `$fetch` saja tidak akan menyediakan [penghapusan duplikasi *network call* dan pencegahan navigasi](/nuxt/getting-started/data-fetching#the-need-for-usefetch-and-useasyncdata). :br
Aku sarankan untuk memakai `$fetch` untuk interaksi sisi *client* (berbasis *event*) atau digabungkan dengan [`useAsyncData`](/nuxt/getting-started/data-fetching#useasyncdata) saat mengambil data awal komponen.
::

### Meneruskan Header Klien ke API

Saat memanggil `useFetch` di server, Nuxt akan menggunakan [`useRequestFetch`](/nuxt/api/composables/use-request-fetch) untuk mem-*proxy* *header* dan *cookie* klien (kecuali *header* yang memang tidak boleh diteruskan, seperti `host`).

```vue
<script setup lang="ts">
const { data } = await useFetch('/api/echo')
</script>
```

```ts
// /api/echo.ts
export default defineEventHandler(event => parseCookies(event))
```

Sebagai alternatif, contoh di bawah ini menunjukkan cara memakai [`useRequestHeaders`](/nuxt/api/composables/use-request-headers) untuk mengakses dan mengirim *cookie* ke API dari *request* sisi server (yang berasal dari *client*). Dengan menggunakan pemanggilan `$fetch` yang isomorfik, kami memastikan bahwa *endpoint* API memiliki akses ke *header* `cookie` yang sama seperti yang awalnya dikirim oleh peramban pengguna. Ini hanya diperlukan kalau kamu tidak memakai `useFetch`.

```vue
<script setup lang="ts">
const headers = useRequestHeaders(['cookie'])

async function getCurrentUser () {
  return await $fetch('/api/me', { headers })
}
</script>
```

::tip
Kamu juga bisa memakai [`useRequestFetch`](/nuxt/api/composables/use-request-fetch) untuk mem-*proxy* *header* ke pemanggilan secara otomatis.
::

::caution
Sangat berhati-hatilah sebelum mem-*proxy* *header* ke API eksternal dan hanya sertakan *header* yang kamu butuhkan. Tidak semua *header* aman untuk dilewati dan bisa memperkenalkan perilaku yang tidak diinginkan. Berikut adalah daftar *header* umum yang TIDAK boleh di-*proxy*:

- `host`, `accept`
- `content-length`, `content-md5`, `content-type`
- `x-forwarded-host`, `x-forwarded-port`, `x-forwarded-proto`
- `cf-connecting-ip`, `cf-ray`
::

## `useFetch`

*Composable* [`useFetch`](/nuxt/api/composables/use-fetch) menggunakan `$fetch` di balik layar untuk membuat *network call* yang aman bagi SSR di fungsi *setup*.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const { data: count } = await useFetch('/api/count')
</script>

<template>
  <p>Page visits: {{ count }}</p>
</template>
```

*Composable* ini adalah *wrapper* dari *composable* [`useAsyncData`](/nuxt/api/composables/use-async-data) dan utilitas `$fetch`.

## `useAsyncData`

*Composable* `useAsyncData` bertanggung jawab untuk membungkus logika *async* dan mengembalikan hasilnya setelah selesai (*resolved*).

::tip
`useFetch(url)` hampir setara dengan `useAsyncData(url, () => event.$fetch(url))`. Ini adalah gula sintaksis (*syntax sugar*) untuk pengalaman pengembang pada kasus penggunaan yang paling umum. (Kamu bisa tahu lebih lanjut tentang `event.fetch` di [`useRequestFetch`](/nuxt/api/composables/use-request-fetch).)
::

:video-accordion{title="Tonton video dari Alexander Lichter untuk memahami lebih dalam perbedaan useFetch dan useAsyncData" videoId="0X-aOpSGabA"}

Ada beberapa kasus di mana penggunaan *composable* [`useFetch`](/nuxt/api/composables/use-fetch) tidak tepat, misalnya saat CMS atau pihak ketiga menyediakan lapisan *query* mereka sendiri. Dalam kasus ini, kamu bisa memakai [`useAsyncData`](/nuxt/api/composables/use-async-data) untuk membungkus pemanggilanmu dan tetap mendapatkan manfaat yang diberikan oleh *composable* tersebut.

```vue [app/pages/users.vue]
<script setup lang="ts">
const { data, error } = await useAsyncData('users', () => myGetFunction('users'))

// Ini juga bisa dilakukan:
const { data, error } = await useAsyncData(() => myGetFunction('users'))
</script>
```

::note
Argumen pertama dari [`useAsyncData`](/nuxt/api/composables/use-async-data) adalah kunci unik yang dipakai untuk *cache* respons dari argumen kedua, yaitu fungsi *query*. Kunci ini bisa diabaikan dengan langsung memberikan fungsi *query*-nya, dan kuncinya akan dibuat secara otomatis.
:br :br
Karena kunci yang dibuat otomatis hanya memperhitungkan lokasi di mana `useAsyncData` dipanggil, kami sangat menyarankan agar kamu selalu membuat kuncimu sendiri untuk menghindari perilaku yang tidak diinginkan, misalnya saat kamu membuat *composable* kustommu sendiri yang membungkus `useAsyncData`.
:br :br
Mengatur kunci juga berguna untuk berbagi data yang sama antar komponen menggunakan [`useNuxtData`](/nuxt/api/composables/use-nuxt-data) atau untuk [memperbarui data tertentu](/nuxt/api/utils/refresh-nuxt-data#refresh-specific-data).
::

```vue [app/pages/users/[id\\].vue]
<script setup lang="ts">
const { id } = useRoute().params

const { data, error } = await useAsyncData(`user:${id}`, () => {
  return myGetFunction('users', { id })
})
</script>
```

*Composable* `useAsyncData` adalah cara yang bagus untuk membungkus dan menunggu beberapa permintaan `$fetch` selesai, lalu memproses hasilnya.

```vue
<script setup lang="ts">
const { data: discounts, status } = await useAsyncData('cart-discount', async (_nuxtApp, { signal }) => {
  const [coupons, offers] = await Promise.all([
    $fetch('/cart/coupons', { signal }),
    $fetch('/cart/offers', { signal }),
  ])

  return { coupons, offers }
})
// discounts.value.coupons
// discounts.value.offers
</script>
```

::note
`useAsyncData` itu untuk mengambil dan meng-*cache* data, bukan untuk memicu *side effect* seperti memanggil aksi Pinia, karena ini bisa menyebabkan perilaku yang tidak diinginkan seperti eksekusi berulang dengan nilai *nullish*. Kalau kamu perlu memicu *side effect*, gunakan utilitas [`callOnce`](/nuxt/api/utils/call-once) untuk melakukannya.

```vue
<script setup lang="ts">
const offersStore = useOffersStore()

// kamu tidak bisa melakukan ini
await useAsyncData(() => offersStore.getOffer(route.params.slug))
</script>
```
::

## Nilai Kembalian

`useFetch` dan `useAsyncData` memiliki nilai kembalian yang sama seperti yang tercantum di bawah ini.

- `data`: hasil dari fungsi *asynchronous* yang dimasukkan.
- `refresh`/`execute`: fungsi yang bisa dipakai untuk memperbarui data yang dikembalikan oleh fungsi `handler`.
- `clear`: fungsi yang bisa dipakai untuk mengatur `data` ke `undefined` (atau nilai `options.default()` kalau disediakan), mengatur `error` ke `undefined`, mengatur `status` ke `idle`, dan menandai *request* yang tertunda sebagai dibatalkan.
- `error`: objek *error* kalau pengambilan data gagal.
- `status`: *string* yang menunjukkan status *request* data (`"idle"`, `"pending"`, `"success"`, `"error"`).

::note
`data`, `error`, dan `status` adalah *Vue ref* yang bisa diakses dengan `.value` di `<script setup>`
::

Secara bawaan, Nuxt akan menunggu sampai `refresh` selesai sebelum bisa dieksekusi lagi.

::note
Kalau kamu tidak mengambil data di server (misalnya, dengan `server: false`), maka data tersebut *tidak akan* diambil sampai proses *hydration* selesai. Ini berarti meskipun kamu melakukan *await* `useFetch` di sisi *client*, `data` akan tetap `undefined` di dalam `<script setup>`.
::

## Opsi

[`useAsyncData`](/nuxt/api/composables/use-async-data) dan [`useFetch`](/nuxt/api/composables/use-fetch) mengembalikan tipe objek yang sama dan menerima sekumpulan opsi umum sebagai argumen terakhir mereka. Opsi ini bisa membantumu mengontrol perilaku *composable*, seperti pemblokiran navigasi, *caching*, atau eksekusi.

### Lazy

Secara bawaan, *composable* pengambilan data akan menunggu penyelesaian fungsi *asynchronous*-nya sebelum menavigasi ke halaman baru dengan memanfaatkan *Suspense* milik Vue. Fitur ini bisa diabaikan pada navigasi sisi *client* dengan opsi `lazy`. Kalau begitu, kamu harus menangani kondisi *loading* secara manual menggunakan nilai `status`.

```vue twoslash [app/app.vue]
<script setup lang="ts">
const { status, data: posts } = useFetch('/api/posts', {
  lazy: true,
})
</script>

<template>
  <!-- kamu perlu menangani kondisi loading -->
  <div v-if="status === 'pending'">
    Loading ...
  </div>
  <div v-else>
    <div v-for="post in posts">
      <!-- lakukan sesuatu -->
    </div>
  </div>
</template>
```

Sebagai alternatif, kamu bisa menggunakan [`useLazyFetch`](/nuxt/api/composables/use-lazy-fetch) dan `useLazyAsyncData` sebagai metode praktis untuk melakukan hal yang sama.

```vue twoslash
<script setup lang="ts">
const { status, data: posts } = useLazyFetch('/api/posts')
</script>
```

### Pengambilan data hanya di Client (*Client-only fetching*)

Secara bawaan, *composable* pengambilan data akan menjalankan fungsi *asynchronous*-nya di lingkungan *client* maupun server. Atur opsi `server` ke `false` untuk melakukan pemanggilan hanya di sisi *client*. Pada *load* awal, data tidak akan diambil sebelum *hydration* selesai jadi kamu harus menangani kondisi *pending*, meskipun pada navigasi sisi *client* berikutnya data akan ditunggu sebelum halaman dimuat.

Kalau digabungkan dengan opsi `lazy`, ini bisa berguna untuk data yang tidak dibutuhkan pada *render* pertama (misalnya, data yang tidak sensitif terhadap SEO).

```ts twoslash
/* Pemanggilan ini dilakukan sebelum hydrasi */
const articles = await useFetch('/api/article')

/* Pemanggilan ini hanya akan dilakukan di client */
const { status, data: comments } = useFetch('/api/comments', {
  lazy: true,
  server: false,
})
```

*Composable* `useFetch` memang dimaksudkan untuk dipanggil di metode *setup* atau dipanggil langsung di tingkat atas fungsi dalam *lifecycle hooks*, kalau tidak sebaiknya kamu pakai [metode `$fetch`](/nuxt/getting-started/data-fetching#fetch).

### Meminimalkan Ukuran Payload

Opsi `pick` membantumu meminimalkan ukuran *payload* yang disimpan di dokumen HTML-mu dengan hanya memilih *field* yang kamu inginkan dari hasil *composable*.

```vue
<script setup lang="ts">
/* hanya ambil field yang dipakai di template-mu */
const { data: mountain } = await useFetch('/api/mountains/everest', {
  pick: ['title', 'description'],
})
</script>

<template>
  <h1>{{ mountain.title }}</h1>
  <p>{{ mountain.description }}</p>
</template>
```

Kalau kamu butuh kendali lebih atau memetakan (*map*) ke beberapa objek, kamu bisa memakai fungsi `transform` untuk mengubah hasil *query*-nya.

```ts
const { data: mountains } = await useFetch('/api/mountains', {
  transform: (mountains) => {
    return mountains.map(mountain => ({ title: mountain.title, description: mountain.description }))
  },
})
```

::note
Baik `pick` maupun `transform` tidak mencegah data yang tidak diinginkan untuk diambil pada awalnya. Tapi keduanya akan mencegah data yang tidak diinginkan agar tidak ditambahkan ke *payload* yang ditransfer dari server ke *client*.
::

### Caching dan Pengambilan Ulang (*Refetching*)

#### Kunci (*Keys*)

[`useFetch`](/nuxt/api/composables/use-fetch) dan [`useAsyncData`](/nuxt/api/composables/use-async-data) menggunakan kunci untuk mencegah pengambilan ulang data yang sama.

- [`useFetch`](/nuxt/api/composables/use-fetch) menghasilkan kunci dari URL, opsi *fetch*, dan lokasi pemanggilan di kode sumbermu. Ini berarti dua pemanggilan `useFetch` dengan URL yang sama di komponen berbeda akan memiliki kunci yang **berbeda** dan masing-masing akan melakukan *request* sendiri. Untuk berbagi data yang sama antar beberapa komponen, berikan `key` eksplisit yang sama di objek `options` yang diberikan sebagai argumen terakhir.
- [`useAsyncData`](/nuxt/api/composables/use-async-data) menggunakan argumen pertamanya sebagai kunci kalau itu berupa *string*. Kalau argumen pertamanya adalah fungsi *handler* yang menjalankan *query*, maka kunci yang unik berdasarkan lokasi pemanggilan `useAsyncData` di kode sumbermu akan dibuatkan otomatis.

::tip
Untuk mendapatkan data yang di-*cache* berdasarkan kuncinya, kamu bisa memakai [`useNuxtData`](/nuxt/api/composables/use-nuxt-data)
::

:video-accordion{title="Tonton video dari Vue School tentang caching data dengan opsi key" videoId="1026410044" platform="vimeo"}

#### State Bersama dan Konsistensi Opsi

Ketika beberapa komponen menggunakan kunci yang sama dengan `useAsyncData` atau `useFetch`, mereka akan berbagi *ref* `data`, `error`, dan `status` yang sama. Ini memastikan konsistensi di seluruh komponen tapi mengharuskan beberapa opsi untuk konsisten.

Opsi berikut **harus konsisten** di semua pemanggilan dengan kunci yang sama:
- fungsi `handler`
- opsi `deep`
- fungsi `transform`
- *array* `pick`
- fungsi `getCachedData`
- nilai `default`

```ts
// ❌ Ini akan memicu peringatan di mode pengembangan
const { data: users1 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { deep: false })
const { data: users2 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { deep: true })
```

Opsi berikut **boleh berbeda** dengan aman tanpa memicu peringatan:
- `server`
- `lazy`
- `immediate`
- `dedupe`
- `watch`

```ts
// ✅ Ini diperbolehkan
const { data: users1 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { immediate: true })
const { data: users2 } = useAsyncData('users', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }), { immediate: false })
```

Kalau kamu butuh instansi yang independen, gunakan kunci yang berbeda:

```ts
// Ini adalah instansi yang sepenuhnya independen
const { data: users1 } = useAsyncData('users-1', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }))
const { data: users2 } = useAsyncData('users-2', (_nuxtApp, { signal }) => $fetch('/api/users', { signal }))
```

#### Kunci Reaktif (*Reactive Keys*)

Kamu bisa memakai *computed ref*, *plain ref*, atau fungsi *getter* sebagai kunci, yang memungkinkan pengambilan data dinamis yang otomatis diperbarui saat *dependency* berubah:

```ts
// Menggunakan properti computed sebagai kunci
const userId = ref('123')
const { data: user } = useAsyncData(
  computed(() => `user-${userId.value}`),
  () => fetchUser(userId.value),
)

// Saat userId berubah, data akan otomatis di-fetch ulang
// dan data lama akan dibersihkan kalau tidak ada komponen lain yang menggunakannya
userId.value = '456'
```

#### Refresh dan Execute

Kalau kamu ingin mengambil atau memperbarui data secara manual, gunakan fungsi `execute` atau `refresh` yang disediakan oleh *composable*.

```vue twoslash
<script setup lang="ts">
const { data, error, execute, refresh } = await useFetch('/api/users')
</script>

<template>
  <div>
    <p>{{ data }}</p>
    <button @click="() => refresh()">
      Perbarui data
    </button>
  </div>
</template>
```

Fungsi `execute` adalah alias untuk `refresh` yang bekerja dengan cara yang persis sama tapi lebih semantik untuk kasus di mana *fetch* [tidak langsung dieksekusi (*not immediate*)](/nuxt/getting-started/data-fetching#not-immediate).

::tip
Untuk mengambil ulang atau menghapus (*invalidate*) data yang di-*cache* secara global, lihat [`clearNuxtData`](/nuxt/api/utils/clear-nuxt-data) dan [`refreshNuxtData`](/nuxt/api/utils/refresh-nuxt-data).
::

#### Clear

Kalau kamu ingin menghapus data yang diberikan, dengan alasan apa pun, tanpa perlu tahu kunci spesifik yang harus diberikan ke `clearNuxtData`, kamu bisa memakai fungsi `clear` yang disediakan oleh *composable*.

```vue twoslash
<script setup lang="ts">
const { data, clear } = await useFetch('/api/users')

const route = useRoute()
watch(() => route.path, (path) => {
  if (path === '/') {
    clear()
  }
})
</script>
```

#### Watch

Untuk menjalankan ulang fungsi pengambilan datamu setiap kali nilai reaktif lain di aplikasimu berubah, gunakan opsi `watch`. Kamu bisa menggunakannya untuk satu atau beberapa elemen yang bisa di-*watch*.

```vue twoslash
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch('/api/users', {
  /* Mengubah id akan memicu refetch */
  watch: [id],
})
</script>
```

Perhatikan bahwa men-*watch* nilai reaktif **tidak akan mengubah URL yang di-*fetch***. Misalnya, ini akan terus mengambil ID awal pengguna yang sama karena URL dibangun saat fungsi itu dipanggil.

```vue
<script setup lang="ts">
const id = ref(1)

const { data, error, refresh } = await useFetch(`/api/users/${id.value}`, {
  watch: [id],
})
</script>
```

Kalau kamu perlu mengubah URL berdasarkan nilai reaktif, mungkin kamu ingin menggunakan [*computed URL*](/nuxt/getting-started/data-fetching#computed-url) sebagai gantinya.

Saat opsi *fetch* reaktif diberikan, mereka akan secara otomatis di-*watch* dan memicu *refetch*. Dalam beberapa kasus, bisa berguna untuk mengabaikan perilaku ini dengan menentukan `watch: false`.

```ts
const id = ref(1)

// Tidak akan otomatis refetch saat id berubah
const { data, execute } = await useFetch('/api/users', {
  query: { id }, // id diwatch secara bawaan
  watch: false, // menonaktifkan watching id secara otomatis
})

// tidak memicu refetch
id.value = 2
```

#### Computed URL

Terkadang kamu mungkin perlu menghitung URL dari nilai reaktif, dan memperbarui data setiap kali nilainya berubah. Alih-alih harus merangkai solusi yang rumit, kamu bisa melampirkan setiap *param* sebagai nilai reaktif. Nuxt akan secara otomatis menggunakan nilai reaktif tersebut dan melakukan *fetch* ulang setiap kali nilainya berubah.

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch('/api/user', {
  query: {
    user_id: id,
  },
})
</script>
```

Untuk konstruksi URL yang lebih kompleks, kamu bisa menggunakan *callback* sebagai [*computed getter*](https://vuejs.org/guide/essentials/computed) yang mengembalikan *string* URL.

Setiap kali *dependency* berubah, data akan diambil menggunakan URL yang baru dibangun. Gabungkan ini dengan [*not-immediate*](/nuxt/getting-started/data-fetching#not-immediate), dan kamu bisa menunggu sampai elemen reaktif berubah sebelum melakukan *fetch*.

```vue
<script setup lang="ts">
const id = ref(null)

const { data, status } = useLazyFetch(() => `/api/users/${id.value}`, {
  immediate: false,
})
</script>

<template>
  <div>
    <!-- nonaktifkan input saat sedang fetch -->
    <input
      v-model="id"
      type="number"
      :disabled="status === 'pending'"
    >

    <div v-if="status === 'idle'">
      Ketik ID pengguna
    </div>

    <div v-else-if="status === 'pending'">
      Memuat ...
    </div>

    <div v-else>
      {{ data }}
    </div>
  </div>
</template>
```

Kalau kamu perlu memaksa *refresh* saat nilai reaktif lain berubah, kamu juga bisa [men-*watch* nilai lain](/nuxt/getting-started/data-fetching#watch).

### Not Immediate

*Composable* `useFetch` akan mulai mengambil data saat itu juga saat dipanggil. Kamu bisa mencegah ini dengan mengatur `immediate: false`, misalnya, untuk menunggu interaksi pengguna.

Dengan begitu, kamu akan membutuhkan `status` untuk menangani siklus hidup *fetch*, dan `execute` untuk memulai pengambilan data.

```vue
<script setup lang="ts">
const { data, error, execute, status } = await useLazyFetch('/api/comments', {
  immediate: false,
})
</script>

<template>
  <div v-if="status === 'idle'">
    <button @click="execute">
      Ambil data
    </button>
  </div>

  <div v-else-if="status === 'pending'">
    Memuat komentar...
  </div>

  <div v-else>
    {{ data }}
  </div>
</template>
```

Untuk kendali yang lebih halus, variabel `status` bisa berupa:

- `idle` saat *fetch* belum dimulai
- `pending` saat *fetch* sudah dimulai tapi belum selesai
- `error` saat *fetch* gagal
- `success` saat *fetch* berhasil diselesaikan

## Meneruskan Header dan Cookie

Saat kita memanggil `$fetch` di peramban, *header* pengguna seperti `cookie` akan langsung dikirim ke API.

Biasanya, saat *server-side-rendering*, karena pertimbangan keamanan, `$fetch` tidak akan menyertakan *cookie* peramban pengguna, ataupun meneruskan *cookie* dari respons *fetch*.

Namun, saat memanggil `useFetch` dengan URL relatif di server, Nuxt akan menggunakan [`useRequestFetch`](/nuxt/api/composables/use-request-fetch) untuk mem-*proxy* *header* dan *cookie* (kecuali *header* yang memang tidak boleh diteruskan, seperti `host`).

### Meneruskan Cookie dari Panggilan API Sisi Server ke Respons SSR

Kalau kamu ingin meneruskan/mem-*proxy* *cookie* ke arah sebaliknya, dari *request* internal kembali ke *client*, kamu harus menangani ini sendiri.

```ts [app/composables/fetch.ts]
import type { H3Event } from 'h3'

export const fetchWithCookie = async (event: H3Event, url: string) => {
  /* Dapatkan respons dari endpoint server */
  const res = await $fetch.raw(url)
  /* Ambil cookie dari respons */
  const cookies = res.headers.getSetCookie()
  /* Lampirkan setiap cookie ke Request masuk kita */
  for (const cookie of cookies) {
    event.res.headers.append('set-cookie', cookie)
  }
  /* Kembalikan data dari respons */
  return res._data
}
```

```vue
<script setup lang="ts">
// Composable ini akan otomatis meneruskan cookie ke client
const event = useRequestEvent()

const { data: result } = await useAsyncData(() => fetchWithCookie(event!, '/api/with-cookie'))

onMounted(() => console.log(document.cookie))
</script>
```

## Menserialisasi Data Dari Server ke Client

Saat menggunakan `useAsyncData` dan `useLazyAsyncData` untuk mentransfer data yang diambil di server ke *client* (serta hal lain apa pun yang memanfaatkan [*Nuxt payload*](/nuxt/api/composables/use-nuxt-app#payload)), *payload* tersebut diserialisasi dengan [`devalue`](https://github.com/sveltejs/devalue). Ini memungkinkan kami untuk mentransfer tidak hanya JSON dasar, tapi juga untuk menserialisasi dan menghidupkan-kembalikan/mendeserialisasi jenis data yang lebih canggih, seperti *regular expressions*, *Dates*, *Map* dan *Set*, `ref`, `reactive`, `shallowRef`, `shallowReactive`, dan `NuxtError` - dan lainnya.

Kamu juga bisa mendefinisikan *serializer/deserializer* buatanmu sendiri untuk tipe yang tidak didukung oleh Nuxt. Kamu bisa baca lebih lanjut di dokumentasi [`useNuxtApp`](/nuxt/api/composables/use-nuxt-app#payload).

::note
Perhatikan bahwa ini *tidak berlaku* untuk data yang berasal dari *server route*mu saat diambil dengan `$fetch` atau `useFetch` - lihat bagian selanjutnya untuk informasi lebih lanjut.
::

## Menserialisasi Data Dari API Routes

Saat mengambil data dari direktori `server`, respons diserialisasi menggunakan `JSON.stringify`. Namun, karena serialisasi terbatas hanya pada tipe primitif JavaScript, Nuxt berusaha sebaik mungkin untuk mengkonversi tipe *return* dari `$fetch` dan [`useFetch`](/nuxt/api/composables/use-fetch) agar cocok dengan nilai aslinya.

::read-more{icon="i-simple-icons-mdnwebdocs" to="https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/stringify#description" target="_blank"}
Pelajari lebih lanjut tentang batasan `JSON.stringify`.
::

### Contoh

```ts [server/api/foo.ts]
export default defineEventHandler(() => {
  return new Date()
})
```

```vue [app/app.vue]
<script setup lang="ts">
// Tipe 'data' diinfer sebagai string meskipun kita mengembalikan objek Date
const { data } = await useFetch('/api/foo')
</script>
```

### Fungsi Serializer Kustom

Untuk mengkustomisasi perilaku serialisasi, kamu bisa mendefinisikan fungsi `toJSON` pada objek yang kamu kembalikan. Kalau kamu mendefinisikan metode `toJSON`, Nuxt akan menghormati tipe *return* dari fungsi tersebut dan tidak akan mencoba mengkonversi tipe-nya.

```ts [server/api/bar.ts]
export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    toJSON () {
      return {
        createdAt: {
          year: this.createdAt.getFullYear(),
          month: this.createdAt.getMonth(),
          day: this.createdAt.getDate(),
        },
      }
    },
  }
  return data
})
```

```vue [app/app.vue]
<script setup lang="ts">
// Tipe 'data' diinfer sebagai
// {
//   createdAt: {
//     year: number
//     month: number
//     day: number
//   }
// }
const { data } = await useFetch('/api/bar')
</script>
```

### Menggunakan Serializer Alternatif

Saat ini Nuxt tidak mendukung *serializer* alternatif selain `JSON.stringify`. Namun, kamu bisa mengembalikan *payload*-mu sebagai *string* normal dan memanfaatkan metode `toJSON` untuk menjaga keamanan tipe.

Pada contoh di bawah ini, kami memakai [superjson](https://github.com/flightcontrolhq/superjson) sebagai *serializer* kami.

```ts [server/api/superjson.ts]
import superjson from 'superjson'

export default defineEventHandler(() => {
  const data = {
    createdAt: new Date(),

    // Solusi sementara untuk konversi tipe
    toJSON () {
      return this
    },
  }

  // Serialisasi output menjadi string, menggunakan superjson
  return superjson.stringify(data) as unknown as typeof data
})
```

```vue [app/app.vue]
<script setup lang="ts">
import superjson from 'superjson'

// `date` diinfer sebagai { createdAt: Date } dan kamu bisa dengan aman menggunakan metode objek Date
const { data } = await useFetch('/api/superjson', {
  transform: (value) => {
    return superjson.parse(value as unknown as string)
  },
})
</script>
```

## Resep (*Recipes*)

### Mengonsumsi SSE (Server-Sent Events) melalui POST request

::tip
Kalau kamu mengonsumsi SSE melalui *GET request*, kamu bisa memakai [`EventSource`](https://developer.mozilla.org/en-US/docs/Web/API/EventSource) atau *composable* VueUse [`useEventSource`](https://vueuse.org/core/useeventsource/).
::

Saat mengonsumsi SSE melalui *POST request*, kamu perlu menangani koneksi secara manual. Begini caranya:

```ts
// Buat POST request ke endpoint SSE
const response = await $fetch<ReadableStream>('/chats/ask-ai', {
  method: 'POST',
  body: {
    query: 'Hello AI, how are you?',
  },
  responseType: 'stream',
})

// Buat ReadableStream baru dari respons dengan TextDecoderStream untuk mendapatkan datanya sebagai teks
const reader = response.pipeThrough(new TextDecoderStream()).getReader()

// Baca chunk data saat kita menerimanya
while (true) {
  const { value, done } = await reader.read()

  if (done) { break }

  console.log('Diterima:', value)
}
```

### Membuat Permintaan Paralel

Saat *request* tidak saling bergantung, kamu bisa melakukannya secara paralel dengan `Promise.all()` untuk meningkatkan performa.

```ts
const { data } = await useAsyncData((_nuxtApp, { signal }) => {
  return Promise.all([
    $fetch('/api/comments/', { signal }),
    $fetch('/api/author/12', { signal }),
  ])
})

const comments = computed(() => data.value?.[0])
const author = computed(() => data.value?.[1])
```
