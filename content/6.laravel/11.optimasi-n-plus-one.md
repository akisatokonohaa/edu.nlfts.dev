# Optimasi Query & Masalah N+1

**N+1 Query Problem** adalah salah satu masalah penurunan performa (*performance bottleneck*) paling umum dalam pengembangan aplikasi berbasis **Object-Relational Mapping (ORM)**, termasuk Laravel Eloquent.

Masalah ini terjadi ketika aplikasi mengeksekusi puluhan hingga ribuan query SQL database terpisah secara berulang di dalam looping, padahal data tersebut bisa diambil dalam 1 atau 2 query teroptimasi.

---

## 1. Memahami Formula $1 + N$

Formula matematis dari masalah ini adalah:

$$\text{Total Query} = 1 + N$$

- **1 Query Awal:** Mengambil daftar record induk (*parent records*), misalnya mengambil 50 data postingan.
- **N Query Tambahan:** Untuk setiap baris (sebanyak $N = 50$), aplikasi menjalankan query terpisah untuk mengambil data relasinya (misalnya data Penulis / *Author*).

### Ilustrasi Kode yang Bermasalah (*Lazy Loading*)

```php [app/Http/Controllers/PostController.php]
// Query 1: Mengambil 50 postingan (1 query)
$posts = Post::all(); 

return view('posts.index', compact('posts'));
```

Di template Blade, pengembang mengakses relasi `author`:

```blade [resources/views/posts/index.blade.php]
@foreach ($posts as $post)
    <article>
        <h2>{{ $post->title }}</h2>
        <!-- SETIAP LOOP INI MENJALANKAN: SELECT * FROM users WHERE id = post.user_id -->
        <p>Penulis: {{ $post->author->name }}</p> 
    </article>
@endforeach
```

::alert{type="danger" icon="lucide:alert-octagon"}
Jika terdapat **100 postingan**, maka total query yang dieksekusi adalah **1 + 100 = 101 query database!** Ini membuang resource server dan membuat response time halaman menjadi sangat lambat (*high latency*).
::

---

## 2. Solusi: Menerapkan Eager Loading (`with`)

Solusi utama untuk mengatasi N+1 Query Problem adalah **Eager Loading** (pemuatan data relasi di awal). Eager loading menggunakan klausa SQL `IN (...)` untuk mengambil seluruh relasi sekaligus.

### Kode Setelah Dioptimasi

Cukup tambahkan method `with('namaRelasi')` pada query Eloquent Anda:

```php [app/Http/Controllers/PostController.php]
// Hanya mengeksekusi 2 query SQL terlepas dari berapa pun jumlah datanya!
$posts = Post::with('author')->latest()->get();

return view('posts.index', compact('posts'));
```

### Apa yang Terjadi di Balik Layar?

Laravel secara cerdas mengeksekusi 2 query efisien:

```sql
-- Query 1: Mengambil 100 data postingan
SELECT * FROM posts ORDER BY created_at DESC;

-- Query 2: Mengambil seluruh relasi author dalam 1 query batch
SELECT * FROM users WHERE id IN (1, 2, 5, 8, 12, 19, ...);
```

---

## 3. Ragam Teknik Eager Loading

::tabs
::tabs-item{label="1. Memuat Banyak Relasi Sekaligus"}
```php
// Mengambil data postingan beserta relasi author DAN kategori
$posts = Post::with(['author', 'category'])->get();
```
::

::tabs-item{label="2. Relasi Bersarang (Nested Eager Loading)"}
```php
// Mengambil postingan beserta komentar, dan setiap komentar memuat profil penggunanya
$posts = Post::with(['comments.user', 'author'])->get();
```
::

::tabs-item{label="3. Lazy Eager Loading (load)"}
Jika instance model sudah terlanjur diambil, Anda bisa memuat relasinya belakangan:
```php
$posts = Post::all();

if ($syaratTertentu) {
    $posts->load('author'); // Menjalankan query batch relasi
}
```
::
::

## 4. Pencegahan Otomatis di Mode Development

Untuk memastikan tim pengembang tidak sengaja menulis kode yang menyebabkan N+1 di masa depan, aktifkan fitur **Strict Mode / Prevent Lazy Loading** pada file `AppServiceProvider`:

```php [app/Providers/AppServiceProvider.php]
namespace App\Providers;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Support\ServiceProvider;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        // Mencegah lazy loading saat aplikasi berjalan di lingkungan lokal/development.
        // Jika ada lazy loading yang tidak sengaja terjadi, Laravel akan melempar Exception secara eksplisit.
        Model::preventLazyLoading(! $this->app->isProduction());
    }
}
```

## 5. Ringkasan Perbandingan Performa

| Aspek | Tanpa Eager Loading (Lazy Loading) | Dengan Eager Loading (`with()`) |
| :--- | :--- | :--- |
| **Jumlah Query untuk 100 Data** | 101 Query SQL | **Hanya 2 Query SQL** |
| **Beban Server Database** | Sangat Tinggi (Banyak round-trip) | **Sangat Ringan** |
| **Kecepatan Render Halaman** | Lambat (bisa >1.2 detik) | **Sangat Cepat (<50 milidetik)** |
| **Skalabilitas Aplikasi** | Rentan Crash saat trafik naik | **Siap Skala Tinggi** |
