# Database & Migrations

**Migration** di Laravel berfungsi seperti *Version Control System* (seperti Git) khusus untuk struktur database Anda. Alih-alih membuat atau mengubah tabel secara manual menggunakan phpMyAdmin atau DBeaver, pengembang mendefinisikan skema tabel menggunakan kode PHP yang terstruktur dan dapat direplikasi di seluruh anggota tim.

---

## 1. Konfigurasi Koneksi Database di `.env`

Konfigurasi koneksi database diatur di dalam file `.env` pada root proyek. 

::tabs
::tabs-item{label="SQLite (Default Laravel Modern)"}
Secara default, Laravel modern menggunakan **SQLite** karena tidak memerlukan instalasi server database eksternal dan langsung siap digunakan:

```env [.env]
DB_CONNECTION=sqlite
# DB_HOST, DB_PORT, DB_USERNAME, DB_PASSWORD tidak diperlukan untuk sqlite
```
> File database otomatis tersimpan di `database/database.sqlite`.
::

::tabs-item{label="MySQL / MariaDB"}
Jika Anda menggunakan MySQL (misalnya via Laragon, XAMPP, atau Docker):

```env [.env]
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=laravel_db
DB_USERNAME=root
DB_PASSWORD=
```
::

::tabs-item{label="PostgreSQL"}
Jika Anda menggunakan PostgreSQL:

```env [.env]
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=laravel_db
DB_USERNAME=postgres
DB_PASSWORD=secret
```
::
::

## 2. Membuat File Migration Baru

Gunakan perintah Artisan `make:migration` untuk membuat file skema baru:

```bash [Terminal]
php artisan make:migration create_posts_table
```

Laravel akan membuat file di dalam folder `database/migrations/` dengan format nama berstempel waktu:

```
database/migrations/2026_08_19_070000_create_posts_table.php
```

Format waktu di depan file memastikan urutan eksekusi migrasi berjalan secara kronologis dan konsisten.

---

## 3. Menulis Definisi Skema Tabel

Buka file migrasi yang baru dibuat. File tersebut memiliki dua method utama:
- `up()`: Dijalankan saat migrasi dieksekusi (membuat atau memodifikasi tabel).
- `down()`: Dijalankan saat migrasi di-rollback (membatalkan perubahan).

```php [database/migrations/2026_08_19_070000_create_posts_table.php]
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::create('posts', function (Blueprint $table) {
            $table->id(); // Kolom ID Primary Key (Auto Increment BigInt)
            $table->string('title', 200); // Kolom VARCHAR(200)
            $table->string('slug')->unique(); // Kolom VARCHAR unik
            $table->text('content'); // Kolom TEXT panjang
            $table->enum('status', ['draft', 'published'])->default('draft');
            $table->foreignId('user_id')->constrained()->cascadeOnDelete(); // Foreign key ke tabel users
            $table->timestamps(); // Kolom created_at & updated_at otomatis
        });
    }

    public function down(): void
    {
        Schema::dropIfExists('posts');
    }
};
```

## 4. Referensi Lengkap Perintah Migrate

Laravel menyediakan beragam perintah Artisan untuk mengelola siklus hidup migrasi database:

::card-group
::card{title="php artisan migrate" icon="lucide:play"}
Menjalankan seluruh file migrasi yang **belum pernah dijalankan** sebelumnya.
::
::card{title="php artisan migrate:fresh" icon="lucide:trash-2"}
**Menghapus (*drop*) seluruh tabel** di database dan menjalankan ulang semua migrasi dari awal.
::
::card{title="php artisan migrate:rollback" icon="lucide:undo-2"}
Membatalkan (rollback) kelompok migrasi terakhir yang baru saja dijalankan.
::
::card{title="php artisan migrate:status" icon="lucide:list-checks"}
Menampilkan tabel status seluruh file migrasi (apakah statusnya *Ran: Yes* atau *Ran: No*).
::
::card{title="php artisan migrate:refresh" icon="lucide:refresh-cw"}
Mereset seluruh migrasi dengan menjalankan method `down()` lalu menjalankan ulang `up()`.
::
::card{title="php artisan migrate:reset" icon="lucide:rotate-ccw"}
Membatalkan seluruh migrasi yang pernah dijalankan di aplikasi, mengosongkan skema database.
::
::

---

## 5. Perbedaan `migrate:fresh` vs `migrate:refresh`

| Aspek | `migrate:fresh` | `migrate:refresh` |
| :--- | :--- | :--- |
| **Cara Kerja** | Langsung melakukan `DROP ALL TABLES` tanpa mengeksekusi method `down()`. | Menjalankan method `down()` satu per satu dari setiap file migrasi sebelum menjalankan `up()`. |
| **Kecepatan** | **Sangat Cepat** (Rekomendasi Utama saat tahap *development*). | Sedikit lebih lambat karena memproses setiap rollback. |
| **Penggunaan Ideal** | Mengulang struktur database lokal dengan cepat. | Menguji apakah method `down()` pada migrasi bekerja dengan benar. |

::alert{type="tip" icon="lucide:sparkles"}
Untuk mereset database sekaligus mengisi ulang data dummy pengujian, gunakan kombinasi:
```bash [Terminal]
php artisan migrate:fresh --seed
```
