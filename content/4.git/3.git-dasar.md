## Sesi 1: Inisialisasi Proyek & Push Pertama Kali ke GitHub

Ikuti langkah-langkah berikut ketika Anda baru pertama kali membuat proyek Laravel lokal dan ingin menghubungkannya ke repositori GitHub baru:

::steps
### 1. Buka Terminal pada Direktori Proyek
Buka terminal VS Code (<kbd>Ctrl</kbd> + <kbd>`</kbd>) atau PowerShell di direktori proyek Anda.

### 2. Inisialisasi Repositori Git Lokal
```bash [Terminal]
git init
```

### 3. Konfigurasi Identitas Pengembang (Wajib)
```bash [Terminal]
git config --global user.name "NamaLengkapAnda"
git config --global user.email "emailanda@example.com"
```
> Atau gunakan opsi `--local` jika ingin konfigurasi identitas hanya berlaku khusus untuk proyek ini saja.

### 4. Tambahkan Semua File ke Staging Area
```bash [Terminal]
git add .
```

### 5. Buat Commit Pertama
```bash [Terminal]
git commit -m "feat: inisialisasi proyek Laravel dan konfigurasi awal"
```

### 6. Hubungkan ke Remote Repositori GitHub
Buat repositori baru di [GitHub](https://github.com/new) (misalnya dengan nama `laravel-app`), lalu salin URL HTTPS repositori tersebut:
```bash [Terminal]
git remote add origin https://github.com/username-anda/laravel-app.git
```

### 7. Ubah Nama Branch ke `main` dan Lakukan Push
```bash [Terminal]
git branch -M main
git push -u origin main
```
::

## Sesi 2: Alur Kerja Pengembangan Harian

Setelah repositori terhubung, gunakan alur kerja berikut untuk memperbarui perubahan kode sehari-hari:

::steps
### 1. Periksa Status File yang Diubah
```bash [Terminal]
git status
```

### 2. Masukkan File ke Staging Area
```bash [Terminal]
git add .
```

### 3. Commit Perubahan dengan Pesan Jelas
Gunakan konvensi pesan commit standar (*Conventional Commits*):
```bash [Terminal]
git commit -m "feat: menambahkan komponen alert dan halaman dashboard"
```

### 4. Kirim (*Push*) ke Repositori GitHub
```bash [Terminal]
git push
```

### 5. Mengambil (*Pull*) Pembaruan Terbaru dari Tim
Jika anggota tim lain melakukan perubahan di repositori remote:
```bash [Terminal]
git pull origin main
```
::

## 1. Pengertian Dasar Git

### Repository

**Repository** atau **repo** adalah tempat Git menyimpan file proyek dan seluruh riwayat perubahannya. Repository dapat berada di komputer lokal atau di layanan seperti GitHub.

### Working Tree

**Working tree** adalah kondisi file proyek yang sedang Anda buka dan edit. Setiap perubahan pada working tree belum tercatat sebagai riwayat Git sampai Anda membuat commit.

### Staging Area

**Staging area** adalah tempat sementara untuk memilih perubahan yang akan disimpan. Perintah `git add` digunakan untuk memasukkan file dari working tree ke staging area.

### Commit

**Commit** adalah catatan perubahan yang disimpan secara permanen di repository lokal. Setiap commit sebaiknya memiliki pesan yang singkat dan menjelaskan perubahan yang dibuat.

### Branch

**Branch** adalah jalur pengembangan yang terpisah dari jalur utama. Branch berguna untuk mengerjakan fitur atau perbaikan tanpa mengganggu branch utama, biasanya bernama `main`.

### Remote

**Remote** adalah alamat repository yang berada di server seperti GitHub. Remote biasanya diberi nama `origin` dan digunakan untuk mengirim atau mengambil perubahan dari repository online.

## 2. Alur Kerja Dasar Git

Alur kerja Git yang paling umum adalah:

1. Membuat atau membuka repository.
2. Mengubah file proyek.
3. Memeriksa perubahan dengan `git status`.
4. Memasukkan perubahan ke staging area dengan `git add`.
5. Menyimpan perubahan dengan `git commit`.
6. Mengirim commit ke GitHub dengan `git push`.

Secara sederhana, alurnya dapat digambarkan seperti berikut:

```text
Working Tree -> Staging Area -> Repository Lokal -> Repository Remote
   mengedit       git add          git commit          git push
```

---

## 3. Membuat Repository Lokal

Masuk ke folder proyek melalui terminal, kemudian jalankan perintah berikut:

```bash
git init
```

Perintah tersebut membuat repository Git baru di dalam folder proyek. Git akan membuat folder tersembunyi bernama `.git` untuk menyimpan konfigurasi dan riwayat perubahan.

Untuk memastikan repository sudah dibuat, jalankan:

```bash
git status
```

Jika berhasil, Git akan menampilkan branch yang sedang digunakan dan status file di dalam proyek.

> Jangan menghapus folder `.git` jika Anda masih ingin menggunakan Git pada proyek tersebut.

---

## 4. Mengecek Status File

Gunakan `git status` sesering mungkin untuk mengetahui kondisi repository:

```bash
git status
```

Perintah ini dapat menunjukkan beberapa kondisi berikut:

- File baru yang belum dilacak (*untracked files*).
- File yang sudah berubah tetapi belum masuk staging area.
- File yang sudah berada di staging area.
- Apakah working tree sudah bersih atau masih memiliki perubahan.

---

## 5. Memasukkan File ke Staging Area

Untuk memasukkan satu file ke staging area, gunakan nama file:

```bash
git add nama-file.html
```

Untuk memasukkan beberapa file sekaligus:

```bash
git add index.html style.css
```

Untuk memasukkan seluruh perubahan di folder saat ini:

```bash
git add .
```

Gunakan `git add .` dengan hati-hati. Pastikan file seperti password, token, folder hasil build, dan file rahasia tidak ikut masuk ke repository.

---

## 6. Membuat File `.gitignore`

File `.gitignore` berisi daftar file atau folder yang tidak perlu disimpan oleh Git. Contoh sederhana untuk proyek Node.js:

```gitignore
node_modules/
.env
.nuxt/
dist/
.output/
```

Buat file bernama `.gitignore` di folder utama proyek, lalu masukkan pola file yang ingin diabaikan. Setelah itu periksa kembali dengan:

```bash
git status
```

File yang cocok dengan aturan `.gitignore` tidak akan ditampilkan sebagai file yang perlu ditambahkan.

---

## 7. Membuat Commit

Setelah perubahan dimasukkan ke staging area, simpan perubahan tersebut dengan perintah:

```bash
git commit -m "Menambahkan halaman utama"
```

Bagian setelah `-m` adalah pesan commit. Gunakan pesan yang jelas dan gunakan kata kerja yang menggambarkan perubahan, misalnya:

```bash
git commit -m "Memperbaiki validasi form kontak"
git commit -m "Menambahkan dokumentasi Git dasar"
```

Commit hanya menyimpan file yang sudah dimasukkan ke staging area. File yang belum di-`add` tidak akan masuk ke commit tersebut.

---

## 8. Melihat Riwayat Commit

Untuk melihat daftar commit, jalankan:

```bash
git log
```

Tampilan yang lebih ringkas dapat dibuat dengan:

```bash
git log --oneline
```

Contoh hasilnya:

```text
c31a2f1 Menambahkan dokumentasi Git dasar
8f4b901 Membuat struktur proyek
```

Kode pendek di sebelah kiri adalah identitas commit yang dapat digunakan untuk memeriksa atau kembali ke perubahan tertentu.

---

## 9. Melihat Perubahan dengan `git diff`

Untuk melihat perubahan yang belum masuk staging area:

```bash
git diff
```

Untuk melihat perubahan yang sudah masuk staging area tetapi belum di-commit:

```bash
git diff --staged
```

Perintah ini berguna untuk memeriksa kembali kode sebelum membuat commit.

---

## 10. Membuat dan Berpindah Branch

Buat branch baru dengan perintah:

```bash
git branch fitur-navbar
```

Berpindah ke branch tersebut dengan:

```bash
git switch fitur-navbar
```

Cara singkat untuk membuat sekaligus berpindah ke branch baru:

```bash
git switch -c fitur-navbar
```

Untuk melihat seluruh branch:

```bash
git branch
```

Tanda `*` menunjukkan branch yang sedang aktif.

Setelah pekerjaan selesai, Anda dapat kembali ke branch utama:

```bash
git switch main
```

> Biasakan membuat branch terpisah untuk fitur baru atau perbaikan agar perubahan lebih mudah diperiksa.

---

## 11. Membatalkan Perubahan

### Membatalkan perubahan yang belum di-stage

Jika perubahan pada file belum dimasukkan ke staging area dan ingin dikembalikan ke kondisi commit terakhir:

```bash
git restore nama-file.html
```

Perubahan pada file tersebut akan dihapus. Gunakan perintah ini hanya jika Anda yakin perubahan tersebut tidak diperlukan.

### Mengeluarkan file dari staging area

Jika file sudah di-`add`, tetapi belum ingin dimasukkan ke commit:

```bash
git restore --staged nama-file.html
```

Perintah ini hanya mengeluarkan file dari staging area. Isi perubahan pada file tetap ada di working tree.

---

## 12. Menghubungkan Repository dengan GitHub

Jika repository GitHub sudah dibuat, tambahkan alamat remote dengan perintah:

```bash
git remote add origin https://github.com/username/nama-repository.git
```

Ganti `username` dan `nama-repository` dengan data repository Anda. Periksa alamat remote dengan:

```bash
git remote -v
```

Jika branch lokal Anda bernama `main`, kirim commit pertama ke GitHub menggunakan:

```bash
git push -u origin main
```

Opsi `-u` menghubungkan branch lokal dengan branch remote. Pada push berikutnya, Anda cukup menjalankan:

```bash
git push
```

---

## 13. Mengambil Perubahan dari GitHub

Untuk mengambil informasi terbaru dari remote tanpa langsung menggabungkannya ke branch aktif:

```bash
git fetch
```

Untuk mengambil sekaligus menggabungkan perubahan dari branch remote:

```bash
git pull
```

Sebelum menjalankan `git pull`, sebaiknya simpan atau commit perubahan lokal terlebih dahulu agar kemungkinan konflik lebih kecil.

---

## Ringkasan Perintah

| Perintah | Fungsi |
| --- | --- |
| `git init` | Membuat repository Git lokal |
| `git status` | Melihat kondisi file dan repository |
| `git add` | Memasukkan perubahan ke staging area |
| `git commit` | Menyimpan perubahan ke riwayat Git |
| `git log` | Melihat riwayat commit |
| `git diff` | Melihat detail perubahan |
| `git branch` | Melihat atau membuat branch |
| `git switch` | Berpindah branch |
| `git remote` | Mengatur alamat repository remote |
| `git push` | Mengirim commit ke remote |
| `git fetch` | Mengambil informasi terbaru dari remote |
| `git pull` | Mengambil dan menggabungkan perubahan remote |
| `git restore` | Mengembalikan atau membatalkan perubahan |

## Latihan Sederhana

Coba praktikkan alur berikut pada folder latihan baru:

```bash
mkdir belajar-git
cd belajar-git
git init
echo "Belajar Git" > README.md
git status
git add README.md
git commit -m "Membuat README pertama"
git log --oneline
```

Jika commit berhasil tampil pada `git log --oneline`, berarti Anda sudah berhasil menggunakan alur dasar Git dari awal sampai akhir.

Pada tahap berikutnya, Anda dapat mempelajari cara menggunakan GitHub secara lebih lanjut, termasuk `clone`, `pull request`, dan kolaborasi menggunakan branch.
